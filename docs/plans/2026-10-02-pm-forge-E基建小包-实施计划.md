## 1. E1 · GitHub Actions CI（半天 → 预计 1.5h）

**文件**：`.github/workflows/ci.yml`（新建）。

**设计**：
- 触发：push 到 main + pull_request；`concurrency: group=ci-${{ github.ref }}`，cancel-in-progress。
- 三个 job（对齐 spec §5 矩阵）：
  1. **site**：setup-node@v4（node 22，满足 engines >=22.12）→ `npm ci`（site/）→ `npm run build`（含 astro check + 两道内容检查）。
  2. **toolkit**：setup-node@v4（node 22）→ `npm ci`（toolkit/）→ `npm run test`（vitest）→ `npm run build`（next build）。**不含 Playwright e2e**（浏览器下载重；spec 矩阵只要求 vitest + next build）。
  3. **python**：setup-python@v5（3.12）+ astral-sh/setup-uv → 三步串行：analysis `uv sync --group dev && uv run pytest -q`；evals `uv sync --group dev && uv run pytest -q`（**全 fixture 测试，无 key 依赖，符合 spec "CI 只跑 schema 校验不花钱"**）；vault-tools `uv sync --extra dev && uv run pytest -q`。
- CI 内 npm 用官方 registry（runner 在境外，直连快；本地装包才走 npmmirror）。

**本地验证（AGENTS 规则 4）**：三模块的 pytest 命令本机逐一实跑确认（uv sync 不破坏现有 .venv）；npm run build/test 已是日常验证。CI 环境差异（干净 checkout）只能靠推送后实跑确认——用 `api.github.com` 公开 API 查 run 结论，不通则明早用户侧复核。

**验收**：main 分支 run 全绿。

## 2. E3 · RSS 全文输出（预计 1h）

**改动**：rss.xml.ts 每条 item 增加 `content` 字段（@astrojs/rss 会输出 `content:encoded`）：用 `astro/container` 的 `experimental_AstroContainer` + `renderToString` 把 entry 渲染成 HTML（集合全 .md，MDX 容器分支不需要）。失败降级路径：容器 API 在 Astro 7 不可用 → 退化为 `entry.body`（markdown 原文）并在 STATUS 记录。

**验证**：新脚本 `scripts/validate-rss.mjs`（devDep: fast-xml-parser，npmmirror 安装）——解析 dist/rss.xml：channel title/link 存在、item ≥1、每条 title/link/pubDate/guid 齐全、`content:encoded` 非空。**串入 build 链**（astro build → check-case-studies → check-links → validate-rss → [E2 的 pagefind]）。

**验收（spec E ③）**：validate-rss 全绿 + 线上 /rss.xml 实抓确认全文标签。

## 4. E2 · 站内搜索复活（Pagefind 1.5.2，预计 2-3h，最大卡）

**前置事实**：2026-09-29 已实测 npmmirror 在架 pagefind 1.5.2 + windows-x64/linux-x64 平台二进制（optionalDependencies 机制，无 CDN 下载，Vercel/CI 均可装）。

**设计**：
- devDep：`pagefind@1.5.2`（site）。
- build 链追加：`pagefind --site dist`（在所有检查之后，产物=dist/pagefind/，纯自托管）。
- 新页面 `/search`（search.astro）：极简自研 UI（输入框 + 结果列表 + aria-live），客户端动态加载 `/pagefind/pagefind.js`（同源产物，**零第三方运行时请求**）；dev 模式无索引时显示"搜索仅生产构建可用"的降级提示。样式对齐站点 token（accent/border 变量），不引 @pagefind/default-ui（样式打架且多一份依赖）。
- Header 导航加"搜索"项（`col-span-2`，置于"关于"之后）——i18n 处理与"案例研究/数据分析/工具箱"的既有硬编码中文模式一致。

**中文分词验收（spec 预钉决策规则）**：IAB 实测生产构建——搜"幻觉"必须命中 evals 计划/基线报告页；搜"RFM"必须命中数据分析页；搜"个人工作台"必须命中对应案例。**三者任一不达预期 → 整卡 revert，ISSUES/STATUS 记录"Pagefind 中文分词不达预期，决策规则触发"**，不恋战。

**回归面**：五步走查（顺导航/看排版/切主题/缩视口/点外链）+ 主题按钮居中复测（0px）+ Lighthouse 六页不回退（≥90，spec E ⑤）+ check-links 死链扫描（/search 链接进 dist，pagefind 资产非 HTML 链接不受影响）。
