## 1. E1 · GitHub Actions CI

**文件**：`.github/workflows/ci.yml`（新建）+ README CI 徽章（**随本卡 commit 同步**）。

**设计**：
- 触发：push 到 main + pull_request；`concurrency: group=ci-${{ github.ref }}`，cancel-in-progress。
- 三个 job，**全部 `runs-on: ubuntu-latest`**（pagefind linux 二进制与 Python 模块都要求）：
  1. **site**：actions/checkout@v4 → setup-node@v4（node 22，cache npm，cache-dependency-path 指 site/package-lock.json）→ `npm ci`（working-directory: site）→ `npm run build`（含 astro check + 两道内容检查）。
  2. **toolkit**：checkout + setup-node 同上 → `npm ci`（toolkit/）→ `npm run test`（vitest）→ `npm run build`（next build）。**不含 Playwright e2e**（spec 矩阵字面只要求 vitest + next build）。
  3. **python**：setup-python@v5（3.12）+ **astral-sh/setup-uv@v6（钉版本）** → 三个模块串行（**有意合并一个 job 省分钟，功能与 spec"矩阵"等价**）：analysis `uv sync --group dev && uv run pytest -q`；evals 同；vault-tools `uv sync --extra dev && uv run pytest -q`。**全 fixture 测试无 key 依赖**（审查员实证 13 个测试文件零真实网络调用），符合 spec "CI 只跑 schema 校验不花钱"。
- CI 内 npm 用官方 registry（runner 境外直连快；本地装包才走 npmmirror）。

**本地验证（AGENTS 规则 4）**：三模块 pytest 命令本机实跑确认；**uv sync 一律先 `--dry-run` 求证语义，不真跑**（审查员实测：真实 sync 会移除本机 vault-tools .venv 的 crosscheck 残留包——CI 无所谓，本机 .venv 不动）。CI 干净环境的最终验证靠推送后 `api.github.com` 公开 API 实查 run 结论。

**验收**：main 分支 run 全绿（spec E ①）。

## 2. E3 · RSS 全文输出

**改动**：rss.xml.ts 每条 item 增加 `content` 字段（@astrojs/rss 输出 `content:encoded`，d.ts:95/114 与 index.js:154 实证）。渲染写法（审查员纠偏，**必改项**）：

```ts
import { experimental_AstroContainer as AstroContainer } from "astro/container";
const container = await AstroContainer.create();
// 每条 entry：
const { Content } = await entry.render();        // render() 返回 RenderResult
const html = await container.renderToString(Content);  // renderToString 接收组件而非 RenderResult
```

失败降级路径：容器 API 在 Astro 7 实跑异常 → 退化为 `entry.body`（markdown 原文）并在 STATUS 记录。

**验证**：新脚本 `scripts/validate-rss.mjs`（devDep: fast-xml-parser，npmmirror 安装）——解析 dist/rss.xml：channel title/link 存在、item ≥1、每条 title/link/pubDate/guid 齐全、`content:encoded` 非空、**content:encoded 内无相对 src/href（审查补充：防阅读器内断链）**。**串入 build 链**（astro build → check-case-studies → check-links → validate-rss → [E2 的 pagefind]）。

**验收点替代论证（spec E ③"RSS 通过验证器"）**：外网 W3C 验证器不稳且非国内可达保障，替代为三重本地证据——XML 结构断言（validate-rss.mjs）+ 本地 preview 实抓 + 线上 /rss.xml 实抓；validate-rss 挂进 build 链成为长期门禁，强于一次性外部验证。
