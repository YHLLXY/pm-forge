> **给执行者**：**这是二期四份计划里优先级最高的一份，建议单独发一个小版本（v0.15），先于任何美化落地。** 它不改动任何视觉。
> **Spec（必须先读）**：
> - `docs/research/2026-10-09-调研-微动效工程化方案.md` §1.3 / §3.4.2 / §3.4.4 / §6 第一优先级

> **一句话概括**：`<ClientRouter />` 的模块脚本**只执行一次**（Astro 官方文档原文：`Bundled module scripts … are only ever executed once`）。而 `search.astro` 与 `data-stories/userbehavior.astro` 的初始化逻辑**全写在模块顶层**——所以**第二次**用站内跳转进这两个页面时，脚本被跳过、新 DOM 上没有任何监听。
>
> **这不是推测，我在线上把它复现出来了。**

## 线上复现记录（2026-10-09，真实浏览器打生产站点）

探针：Playwright，从首页点击搜索链接 → 输入「案例」→ 返回首页 → 再次点击搜索链接 → 再输入「案例」。

**结论**：输入框长得完全正常、也能打字，**但一个字都搜不出来，控制台没有任何报错**——正是"静默失效"。数据故事页同理（`userbehavior.astro` 的脚本是 hoisted `src` 模块，走 URL 去重路径，一样会被跳过）。

### Step 2：整块替换 `<script>`（下面是完整代码，可直接粘贴）

```astro
<script>
  // Pagefind 索引仅存在于生产构建产物（dist/pagefind/）；dev 模式无索引，优雅降级。
  // 不用 import()：Vite 会把动态导入包进预加载助手并在产物里留下 __VITE_PRELOAD__
  // 占位符（实测 ReferenceError）。改用运行时注入 module script，打包器完全不碰它。
  //
  // ⚠️ 必须包成 initSearch() 并挂 astro:page-load：
  // ClientRouter 下"打包后的模块脚本只执行一次"（Astro 官方文档 Script re-execution；
  // astro@7.3.5 的 transitions/swap-functions.js:29-45 用 script.src 或 textContent 做去重键，
  // router.js:82-98 跳过带 data-astro-exec 的脚本）。顶层写法的脚本在第二次站内跳转
  // 进入 /search/ 时会被跳过，新 DOM 上的 #search-input 不会有任何监听 → 输入框静默失效。
  const PF_URL = "/pagefind/pagefind.js";

  type Pagefind = {
    search: (q: string) => Promise<{
      results: { data: () => Promise<{ url: string; excerpt: string; meta?: { title?: string } }> }[];
    }>;
  };
  declare global {
    interface Window {
      __pagefind?: Pagefind;
    }
  }

  function initSearch(): void {
    const input = document.getElementById("search-input") as HTMLInputElement | null;
    const status = document.getElementById("search-status");
    const list = document.getElementById("search-results");
    // 站内跳转到别的页面时本函数也会被调用：缺任一节点就直接返回，不要 null 崩溃
    if (!input || !status || !list) return;
    // 幂等：window load 与 astro:page-load 都会触发本函数，同一份 DOM 只初始化一次
    if (input.dataset.searchBound === "true") return;
    input.dataset.searchBound = "true";

    let pagefind: Pagefind | null = null;
    let loadFailed = false;
    let timer: ReturnType<typeof setTimeout>;

    function loadPagefind(): Promise<Pagefind | null> {
      if (pagefind) return Promise.resolve(pagefind);
      // 二次进入时上一次注入的模块已经把 pf 挂到 window 上，直接复用，不要重复注入 script
      if (window.__pagefind) {
        pagefind = window.__pagefind;
        return Promise.resolve(pagefind);
      }
      if (loadFailed) return Promise.resolve(null);
      return new Promise(resolve => {
        const fail = () => {
          loadFailed = true;
          status.textContent = "搜索索引不可用：生产构建才包含索引（npm run build 后可用）。";
          resolve(null);
        };
        const s = document.createElement("script");
        s.type = "module";
        s.textContent =
          'import * as pf from "' +
          PF_URL +
          '"; window.__pagefind = pf; window.dispatchEvent(new Event("pagefind:ready"));';
        s.onerror = fail;
        window.addEventListener(
          "pagefind:ready",
          () => {
            if (window.__pagefind) {
              pagefind = window.__pagefind;
              resolve(pagefind);
            } else fail();
          },
          { once: true }
        );
        setTimeout(() => {
          if (!pagefind && !loadFailed) fail();
        }, 5000);
        document.head.appendChild(s);
      });
    }

    async function runSearch(query: string) {
      const q = query.trim();
      if (!q) {
        list.innerHTML = "";
        status.textContent = "";
        return;
      }
      const pf = await loadPagefind();
      if (!pf) return;
      const res = await pf.search(q);
      const data = await Promise.all(res.results.slice(0, 20).map(r => r.data()));
      status.textContent = `找到 ${res.results.length} 条结果`;
      list.innerHTML = data
        .map(
          d => `
        <li class="border-border mt-3 rounded-lg border p-3">
          <a class="text-accent font-medium underline decoration-dashed" href="${d.url}">${
            d.meta?.title ?? d.url
          }</a>
          <p class="text-foreground/75 mt-1 text-sm">${d.excerpt}</p>
        </li>`
        )
        .join("");
    }

    input.addEventListener("input", () => {
      clearTimeout(timer);
      timer = setTimeout(() => runSearch(input.value), 200);
    });
  }

  // astro@7.3.5 的 transitions/router.js:414 用 addEventListener("load", onPageLoad) 注册，
  // 保证**首次加载也会触发**，所以不需要再裸调一次 initSearch()。
  // 后续每次站内跳转在 :352 过渡完成后再次触发。
  document.addEventListener("astro:page-load", initSearch);
</script>
```

> **与原文的差异只有两处，且都是必要的**：① 所有 DOM 引用从模块顶层移进 `initSearch()` 局部；② `loadPagefind()` 增加 `window.__pagefind` 复用分支。**搜索逻辑、超时 5000ms、200ms 防抖、`slice(0,20)`、错误文案一字未改。**
> **备选写法**：给脚本加 `data-astro-rerun`（Astro 官方给的另一个方案）。本计划**不选**它——它只保证"重新执行"，而模块顶层的 DOM 引用仍会指向旧节点；`initSearch()` 的写法同时解决两个问题，且与数据故事页保持一致。

结构如下（**原有内部逻辑一行不改地搬进去**，包括移动端降级、IntersectionObserver、scrollama、`#q-run` 的整个 async 回调）：

```astro

  import scrollama, { type ScrollamaInstance } from "scrollama";
  import { BEHAVIORS, DIMS, buildQuery, type QuerySpec } from "@/scripts/story/allowed-queries";

  const METRICS = ["event_count", "user_count"] as const;

  // 跨站内跳转保留：WASM 引擎加载一次就够，二次进入不必重下
  let engineReady = false;
  // 需要在文档被换掉之前销毁的实例（否则 window 上的滚动/尺寸监听会一直累积）
  let io: IntersectionObserver | null = null;
  let scroller: ScrollamaInstance | null = null;

  function teardownStory(): void {
    io?.disconnect();
    io = null;
    scroller?.destroy();
    scroller = null;

    const main = document.getElementById("main-content");
    if (!main) return;
    if (main.dataset.storyBound === "true") return;
    main.dataset.storyBound = "true";

    const isMobileLike =

      window.matchMedia("(max-width: 767px)").matches;

      document.querySelector('a[href="#explore"]')?.remove();

    const rendered = new Set<string>();

      .setup({ step: ".story-step", offset: 0.5 })

    const runBtn = document.getElementById("q-run") as HTMLButtonElement | null;
    runBtn?.addEventListener("click", async () => {

  document.addEventListener("astro:before-swap", teardownStory);
```

> **三个必须做的点**：
> 1. `engineReady` **不要**留在函数内。它是"引擎已下载"的状态，应该跨页面访问保留——否则每次回到故事页都要重下 WASM。

## Task 4：补 reduced-motion 闸门（两个现存缺口）

**Files**：Modify `site/src/styles/global.css`

- [ ] **Step 1：补 `::view-transition-*` 关停**

调研实测：**构建产物里没有 Astro 自带的 `viewtransitions.css`**（`Footer.BxwaP4fT.css` 58,356 字节里 `view-transition` 出现 0 次、`astroFade` 0 次）。也就是说 Astro 官方承诺的"reduce 时禁用全部过渡动画"那段 CSS **没进产物**，现在跑的是 **UA 默认的根交叉淡入淡出**。

在 `global.css` **顶层**（不要放进 `@layer base`——伪元素规则不需要层）追加，逐字复刻自 `astro/components/viewtransitions.css:56-66`：

```css
/* 复刻自 astro/components/viewtransitions.css:56-66（本项目的 Astro 产物没有带上它） */
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*),
  ::view-transition-old(*),
  ::view-transition-new(*) {
    animation: none !important;
  }
  [data-astro-transition-scope] {
    animation: none !important;
  }
}
```

> **一个必须交代的事实（写进注释，别让后来人以为这是唯一正确答案）**：W3C CSSWG 2024-09-24 决议（issue #10267）的方向是"reduce 时 UA 用**纯交叉淡入淡出**、去掉尺寸/位移动画"，而不是完全不动。所以这段 CSS 让本站**比 UA 默认更保守**。两者都属于尊重用户偏好；如果哪天觉得"完全不动"让人不知道页面变了，把它换成弱化的淡入即可。

- [ ] **Step 2：给 `scroll-behavior: smooth` 补 reduce 门**

`site/src/layouts/Layout.astro:47` 的 `<html class="overflow-y-scroll scroll-smooth">` 目前**没有 reduce 门**（现存缺口：开了减弱动态效果的用户，点锚点仍会被平滑滚动）。

改法（二选一，**选 A**）：
- **A（推荐）**：把 `scroll-smooth` 从 html 上拿掉，改到 `global.css`：

```css
@media (prefers-reduced-motion: no-preference) {
  html {
    scroll-behavior: smooth;
  }
}
```

- B：保留 `scroll-smooth`，另加 `@media (prefers-reduced-motion: reduce) { html { scroll-behavior: auto; } }`（能work，但"先开后覆盖"不如 A 干净）。
