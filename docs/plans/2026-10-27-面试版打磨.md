# 面试版打磨（2026-10-27 第 3 轮）

> 触发：用户拿站点去面试前提出 5 个问题（日期、点击迟钝、范围号横杠、工具箱节简陋、缺联系动效）。
> 原则：先量后改；每条都给可复现证据；改不动的地方直说不改。

> 实施后记（2026-10-28 01:15，与计划的偏离）
>
> P1 的原方案只写到「加 viewport 预取」。实测发现**预取本身不够**：预取请求发出去了（`initiatorType: link`），
> 但点卡片仍是 334–798ms —— 因为 Vercel 给 HTML 的默认头是 `public, max-age=0, must-revalidate`，
> Router 真正取页面时还要重新校验一趟。补了一条 `site/vercel.json` 规则：无扩展名的路由给
> `max-age=60, stale-while-revalidate=86400`。改完 click→swap 从 366–581ms 降到 **26–44ms**。
> 这条不在原计划里，是量出来的。
>
> 另外「返回」慢的原因也定位到了：它指向首页，而首页此前没有任何一处预取它（页头是 hover 策略），
> 第一次点返回要等一整趟往返（1472ms）。给返回按钮挂上 viewport 后降到 36ms。

## 0 结论先行

| # | 用户看到的现象 | 实测根因 | 本轮改法 |
|---|---|---|---|
| 1 | 「最近更新」格子里是 11px 小字日期，跟旁边 28–38px 数字完全不是一套；且日期停在 10-07 | 第 6 格沿用 `Datetime size="xs"`（11px）塞进 `height: var(--num-size)`(38px) 的 dd；`latest` 只取**内容**的 pubDatetime 最大值，站点改版永远不反映 | 第 6 格改成与其它 5 格同字号的大数（`10.27` + 小字 `2026`）；`latest` 改为 max(内容最大日期, 站点发版日) |
| 2 | 点大卡片「第一次没反应，等一会才有反应」；点返回同样 | ClientRouter 单页导航：实测**线上** click→swap **366/409/581ms**（本地 22–38ms）。配置里 prefetch 是 `hover`，触摸设备/快速点击拿不到预取，期间页面**零反馈** | 卡片与主链加 `data-astro-prefetch="viewport"`；加 2px 顶部进度条（>150ms 才出现），让"点了"这件事立刻可见 |
| 3 | 正文里一串「横杠」，`26102%` / `4060%` 读不成数 | 不是装饰，是范围号 `~`：`26~102%` 与 `40~60%`。该字体下 `~` 渲染成一条低平横杠，且首位数字丢了 `%`，于是一眼看成两万六千一百零二 | 改写为 `26% 至 102%` / `40% 至 60%`；新增 `check-typography` 门禁拦 `数字~数字` 回潮 |
| 4 | 工具箱一节"简陋" | 截图有效内容只占 740×480 / 1440×810（利用率 30%），四周大片空白；这一节只讲了"是什么"，没讲**为什么做** | 重排：一句初衷 + 三步流水线（输入→证据分层→产出）+ 三张工具卡（输入/产出）+ 带地址栏的浏览器框截图（重裁到内容区）；**不改** toolkit 应用本体 |
| 5 | 结尾缺一个"动了才好看"的联系区 | 首页目前**没有**联系方式区块，Footer 只有 GitHub 一个图标 | 新增 §06 联系方式：同心圆点阵轨道 + 四个通道（微信/QQ/邮箱/GitHub）绕圈运行，点开是二维码/地址面板；二维码从用户截图裁切并**解码校验** |

## 1 实测证据

### 1.1 导航延迟（`docs/tools/measure-nav.mjs`，2026-10-27 23:52）

| 目标 | 点卡片 click→swap | 点返回 click→swap |
|---|---|---|
| 线上 www.yuhailinlxy.com | 581 / 366 / 409 ms | 1166 / 290 / 600 ms |
| 本地 preview | 38 / 22 / 34 ms | 25 / 32 / 36 ms |

线上数字是**没有 hover 预取**时的口径（脚本用 CDP 直接派发 mousedown/up）。真实鼠标用户会先 hover，命中 `hover` 预取后通常 30–80ms；但触摸设备（面试官用手机看）与"移过去立刻点"仍然吃满 400ms+，且这 400ms 里页面**完全没有变化**。

### 1.2 第 6 格

`dd` 计算高度 38px，内部 `<time>` 字号 11px、`text-decoration: none`、无边框 —— 所以"横线"不是样式，是**比例失衡**（11px 字 vs 38px 槽位）。

### 1.3 范围号

`site/src/content/analysis/vegetable-pricing.md` 三处：`26~102%`（第 26 行）、`40~60%`（第 20、26 行）。全站 `[0-9]~[0-9]` 命中 3 处，全在该文件。

### 1.4 截图利用率

`site/src/assets/covers/toolbox.webp` 1440×810：内容实际占 x 355–1090、y 64–540。

## 2 逐项方案

### P0 证据面板第 6 格（30 分钟）

- 值改为 `10.27`（`MM.DD`，与 `/case-studies/` 速览表同一写法），单位槽放 `2026`，标签仍是「最近更新」，注脚「站点改版」。
- 数据源：`src/utils/evidence.ts` 增加 `SITE_RELEASE = "2026-10-27"`，`latest = max(内容 pubDatetime 最大值, SITE_RELEASE)`。发版时改这一处；内容更新仍会自动前移。
- 为什么不用 `updatedDate`：全站 19 个内容文件的 updatedDate 大多等于 pubDatetime，"站点改了"这件事本来就不在内容里。
- 否决：不在客户端算"距今几天"（会引入文本变化 → CLS 风险，原有注释已记录）。

### P1 点击迟钝（1 小时）

1. `Card.astro` 与首页各主链加 `data-astro-prefetch="viewport"`：进入视口即预取，触摸/快速点击也能命中。
   - 保留全局 `prefetchAll: true + hover`（不做全局 viewport：列表页 6 张卡 + 首页 7 处出口，移动端一次性多拉 ~400KB HTML）。
2. 新增 `NavProgress.astro`：顶部 2px 进度线，`astro:before-preparation` 起 150ms 后才显示，`astro:after-swap` 收尾；`prefers-reduced-motion` 下不做动画只显隐。
3. 验收：CDP 限速（Fast 3G）复现慢导航 → 截图证明进度条出现；正常网络下不应看到闪烁。

### P2 范围号（30 分钟）

- 三处改写成 `26% 至 102%`、`40% 至 60%`（补 `%`、去 `~`）。
- 新增 `scripts/check-typography.mjs`：扫 `src/content/**/*.md`，命中 `\d\s*~\s*\d` 即失败；挂进 `npm run build`（第 12 道构建期门禁）。
- 顺带查全角/半角混排：只在同一行同时出现 `，` 与 `,` 时报错？——**否决**：存量文案里中英混排是刻意的，一刀切会误伤。

### P3 工具箱节（2 小时）

结构（沿用 Section 外壳，`accent="toolbox"`）：

```
§ 05 · TOOLKIT / AI PM 工具箱
初衷：把"先取证、再下结论"固化成一条能跑的流水线 —— 每条结论都要能回到证据，回不到就标【待补充】。
[输入材料] → [证据分层：【外部输入】/【行业常识】/【推测】] → [带标注的报告]
┌ 浏览器框：toolbox.yuhailinlxy.com ─────────────┐  ┌ 竞品分析   输入…→产出… ┐
│ 重新裁切到内容区的真实截图                      │  ┌ 用户反馈洞察 …        ┐
└───────────────────────────────────────────────┘  ┌ PRD 草稿    …        ┐
[打开工具箱 ↗] [了解工具与精选报告 →]
```

- 截图：从线上重抓 2× 再裁到内容区（约 1620×1100），不再让 70% 的面积是空白。
- 三条证据标签是真功能（线上页面注脚原文），不是装饰。
- **不做**：不改 toolkit 应用本体 UI（另一个项目、要单独排期）。这一轮只解决"作品集里这一节讲不清初衷"。

### P4 联系方式（3 小时）

布局：`Section id="contact" index="06" zh="联系方式" en="CONTACT"`，内部 12 栅格：左 5 列文案 + 右 7 列轨道图（移动端上下堆叠）。

轨道图：
- 3 条同心圆点阵（`stroke-dasharray` 圆点），半径 40% / 30% / 21%，各自 60/90/120s 反向自转 —— 点阵缓慢漂移，不抢注意力。
- 4 个通道挂在轨道上：微信 / QQ / 邮箱 / GitHub，各自 40–80s 公转，内层反向自转保持**图标永远正立**（不用 `offset-path`：Safari 对 `circle()` 支持不稳，面试官可能用 Mac）。
- 中心：姓氏字「余」+ 一枚缓慢呼吸的绿点（"目前开放机会"）。
- 交互：hover/focus 暂停整套公转（避免"追着点"）；四个通道都是 `<button>`，点开原生 `<dialog>`：微信/QQ 给二维码（200px，白底静区），邮箱给地址 + 复制 + mailto，GitHub 给地址 + 复制 + 打开。
- 无障碍：`<button aria-label>`、dialog 自动焦点陷阱、Esc 关闭、焦点归还；`prefers-reduced-motion` 下所有自转/公转停止，图标固定在四个方位。
- 资源：`site/src/assets/contact/{wechat,qq}.png`（640×640，白底 11% 静区）。**校验**：`zxing-cpp` 解码，内容必须与原始截图一致（微信 `https://u.wechat.com/…`、QQ `https://qm.qq.com/q/…`）。
- 小红书**不加**：没有可核验的主页链接，编一个等于放假链接。若用户给链接，一条 `channels` 配置即可加。

## 3 风险与回滚

| 风险 | 处理 |
|---|---|
| 预取拖慢首屏 / 多耗流量 | 只给卡片与主链加 viewport；实测首页请求数与体积变化写进验收 |
| 进度条闪烁 | 150ms 延迟显示；正常网络下截图证明不出现 |
| 轨道动效影响可读性/晕动 | 60s+ 周期、低对比点阵；reduced-motion 全停 |
| 二维码扫不出来 | 交付前用 zxing-cpp 解码校验；显示尺寸 ≥180px |
| 个人信息外泄 | 只放用户主动提供的微信/QQ/邮箱/GitHub；二维码默认不显示，点开才出现 |
| 某一步改坏 | 每步独立提交；`npm run build` + `npm run lh` 全绿才算完成 |

## 4 验收清单

1. `cmd /c "npm.cmd run build"` → 12 道构建期门禁全绿（含新增 check-typography）。
2. `npm run lh` → 13 页 + 证据面板对齐（6 格）全过。
3. `node docs/tools/measure-nav.mjs` 线上复测：有 hover 的 click→swap 中位数 < 150ms。
4. 截图：首页 1440 浅色/深色、390 移动端、联系区 hover 暂停、dialog 打开、reduced-motion。
5. 二维码解码日志（两条 URL）写进 `docs/reviews/`。
6. 文档：本文件 + `docs/STATUS.md` + `site/README.md`（门禁表加第 12 道）。

## 5 自审记录（写完初稿后逐条挑刺）

| 初稿 | 挑出的问题 | 改后 |
|---|---|---|
| 第 6 格直接写 `2026-10-27` 大字 | 10 个字符在 130px 窄格里会溢出（实测 38px 字号下 `2026.10.27` ≈ 210px） | 改 `10.27` + 小字 `2026`，与速览表 `09.28` 的写法统一 |
| 全局 `defaultStrategy: "viewport"` | 列表页 6 卡 + 首页 7 出口，移动端一次性多拉几百 KB；且会跟首屏图片抢带宽 | 只给卡片/主链加 viewport，全局仍 hover |
| 返回按钮改 `history.back()` | ClientRouter 会拦截 popstate 重新取页，速度不变；且会改变"返回去哪"的语义 | 不改语义，只靠预取 + 进度条解决"觉得没反应" |
| 轨道用 `offset-path: circle()` | Safari 16 支持面不确定，Mac 面试官可能看到图标飞出轨道 | 用"外层自转 + 内层反向自转"的经典做法，兼容性最稳 |
| 联系区放 5 个通道（含小红书） | 小红书没有可核验链接 | 砍到 4 个，理由写进文档 |
| 顺手把 toolkit 应用 UI 也改 | 范围失控，且它有自己的测试与部署链 | 明确写"不做"，列为下一轮可选项 |
