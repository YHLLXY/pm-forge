## Global Constraints

- **不花哨的量化红线**（调研 §6 明确列出的禁止项，逐条照做）：
  - ❌ 数字递增 count-up
  - ❌ 卡片边框变色
  - ❌ `transition:animate="slide"` 或任何横向位移的页面过渡
  - ❌ 逐卡错开的 stagger「瀑布」进场

- **无 JS 时所有内容必须完全可见**（进场动画的硬要求，见 Task 4）。
- **无障碍**：键盘焦点反馈必须与 hover 一致；不破坏 `h1` 唯一性与标题层级。
- **每次新增自定义动效后，必须用 Task 5 的探针在 `reducedMotion:'reduce'` 下复测**——这是实测给的硬要求，不是可选项。

## Task 1：卡片 hover / focus 反馈对齐（P1-1 + P1-2）

**Files**：Modify `site/src/components/Card.astro` 第 39-42 行、第 58-60 行

**问题**：现状 `Card.astro:41` 只有 `transition-shadow duration-200 hover:shadow-2`——**键盘用户 Tab 到卡片时没有任何反馈**，与鼠标 hover 不一致。这是现存的无障碍不一致。

- [ ] **Step 1：替换卡片的 class**

原（`Card.astro:39-42`）：

```html
<a
  href={href}
  class="border-border bg-surface-1 shadow-1 hover:shadow-2 focus-visible:no-underline group flex h-full flex-col overflow-hidden rounded-xl border transition-shadow duration-200"
>
```

改为：

```html
<a
  href={href}
  class="border-border bg-surface-1 shadow-1 group flex h-full flex-col overflow-hidden rounded-xl border transition-[box-shadow,translate] duration-200 ease-out hover:shadow-2 focus-visible:shadow-2 focus-visible:no-underline motion-safe:hover:-translate-y-0.5 motion-safe:focus-visible:-translate-y-0.5"
>
```

- [ ] **Step 2：标题的 hover / focus 对齐**

原（`Card.astro:58-60`）：`class="group-hover:text-accent text-lg leading-snug font-semibold tracking-tight"`
改为：`class="group-hover:text-accent group-focus-visible:text-accent text-lg leading-snug font-semibold tracking-tight"`

- [ ] **Step 3：逐条核对这几个数值的来源（不要自己改）**

| 写法 | 实际值 | 来源 |
|---|---|---|
| `-translate-y-0.5` | `calc(var(--spacing) * -0.5)`，本项目产物 `--spacing: .25rem` → **正好 −2px** | Tailwind v4 产物实测 |
| `duration-200` | `.2s` = **200ms**，与原状一致，**没有改时长** | 产物实测 |
| `ease-out` | `cubic-bezier(0, 0, 0.2, 1)`（`theme.css:435`），**恰好等于 Material 3 的 `easing-standard-decelerate`** | Tailwind 主题 + M3 官方 token |
| `motion-safe:` | 包在 `@media (prefers-reduced-motion: no-preference)` 里 → **reduce 用户只看到阴影变化，没有位移** | Tailwind v4 |
| `hover:` | 本项目 Tailwind v4.3.2 **已自动**给 `hover:` 加 `@media (hover: hover)`（产物里出现 7 次）→ 触屏上不会"粘住" | 产物实测，**不需要自己再包一层** |

> **为什么位移只有 2px**：调研 §4.3 的经验判据是"微反馈位移 ≤ 12px"，而卡片是**大面积元素**，位移越大小概率越容易引起前庭不适。2px 是"卡片轻轻抬起来"的量级，不是"飞起来"。**不要加大**。
> **为什么保留阴影变化**：阴影**不是"运动"**（MDN 的前庭描述针对 scale/pan/位移），保留是合理的；它也是 reduce 用户唯一能看到的反馈。

Expected：13 页四类 ≥90（a11y 必须仍是 100）。

Run（手动）：Tab 键遍历首页卡片 → 每张卡都出现**阴影加深 + 标题变蓝 + 虚线 focus 描边**三者齐备；开"减弱动态效果" → 只有阴影变化，无位移。

## Task 3：prefetch 显式化（P1-4）

**Files**：Modify `site/astro.config.ts`

**为什么**：现在 prefetch 是**隐式默认**（`ClientRouter` 自动开、`prefetchAll: true`、策略 `hover`）。隐式默认会在 Astro 升级时被悄悄改变，而它对流量与体验都有影响。写出来 = 可读 + 可回滚。

- [ ] **Step 1：在 `defineConfig({...})` 里加**

```ts
  // ClientRouter 会默认打开 prefetch 并设 prefetchAll: true
  // （见 node_modules/astro/dist/types/public/config.d.ts:1904 与 :1924；
  //  实现见 astro/components/ClientRouter.astro:151-152 → init({ prefetchAll: true })）
  // 这里显式写出来，避免"隐式默认"在升级时被改变。
  prefetch: {
    prefetchAll: true,
    defaultStrategy: "hover", // 'tap' | 'hover' | 'viewport' | 'load'
  },
```

- [ ] **Step 2：明确不要改的两个方向（写进注释或 commit message）**

- **不要**改成 `viewport`：移动端一进页面就把所有可见卡片全预取，流量开销明显。
- **不要**改成 `false`：prefetch 是 ClientRouter "体感快"的主要来源。
- 单个链接若不该预取：加 `data-astro-prefetch="false"`（官方文档给出的关闭方式）。

Run：`cd site && npm run build`
Expected：全绿。

Run（手动，复用我线上那次的探针）：`hover` 一个站内链接 → DOM 里应**仍然**新增 `<link rel="prefetch">`（行为不变，只是从隐式变显式）。

- [ ] **Step 3：JS 侧 —— 必须挂 `astro:page-load`**

放进 `Main.astro`：

```ts
<script>
  let io: IntersectionObserver | null = null;

  function setupReveal() {
    // 尊重用户偏好：reduce 时什么都不做，内容本来就是可见的
    if (!window.matchMedia("(prefers-reduced-motion: no-preference)").matches) return;
    const targets = document.querySelectorAll<HTMLElement>(".reveal:not(.is-visible)");
    if (!targets.length) return;

    io?.disconnect();
    io = new IntersectionObserver(
      entries => {
        for (const entry of entries) {
          if (!entry.isIntersecting) continue;
          entry.target.classList.add("is-visible");
          io?.unobserve(entry.target);   // 一次性：滚回去不重放
        }
      },
      { rootMargin: "0px 0px -10% 0px" }
    );
    targets.forEach(el => io!.observe(el));
  }

  setupReveal();
  document.addEventListener("astro:page-load", setupReveal);
</script>
```

## 明确不做（逐条都有调研依据，不是偷懒）

| 不做 | 依据 |
|---|---|
| count-up 数字递增 | §3.6：违反 Apple HIG "don't make people wait"；证据面板的数字是事实不是表演；TBT 权重 30，任何 rAF 循环都在送人头 |
| 卡片边框变色 | §3.1：与阴影+上浮重复表达同一件事，且边框变色在浅色底上对比度难控 |
| `transition:animate="slide"` | §3.4.1：横向位移的页面过渡是"花哨"的第一来源 |
| 逐卡 stagger 瀑布进场 | §3.3：典型花哨特征 |
| 循环/呼吸/脉冲动画 | §5.3：如确需必须默认 `paused` |
| `linear()` 弹簧曲线 | §4.2：调研自己把它列进"不建议做" |
| `transition: all` | §5.5 反例（Visual Cinnamon 的真实反例） |
| 封面 `scale-[1.02]` 微缩放 | §3.1 列为可选且"默认不建议"：SVG 内 `<text>` 会一起放大，1.02 下虽基本无感但收益也小 |

## 关于两个"权威依据"的诚实说明（务必照抄进文档，别拔高）

1. **WCAG 对动效的要求**：`prefers-reduced-motion` 相关的 **SC 2.3.3 Animation from Interactions 是 AAA 级**，官方充分技术是 C39 / SCR40 / Gx（**C39 同时认可 `reduce` 与 `no-preference` 两种写法**）。另外 SC 2.2.2（5 秒/自动播放）、SC 2.3.1（闪烁 3Hz、341×256 CSS px = 87,296、20 cd/m²）。
2. **官方设计系统的时长数值**：Material 3 与 IBM Carbon 的 token 是**抄来的**（M3 `short4=200ms`、`medium2=300ms`、`easing-standard-decelerate=cubic-bezier(0,0,0,1)`；Carbon `moderate-01=150ms`，官方称 "Default transition speed"，缓动 `cubic-bezier(0.2,0,0.38,0.9)`）。**Apple HIG 逐字读完了 Motion 章节：只给原则、没有任何时长/缓动数字**——所以**不要写"Apple 建议 xxx ms"**。
3. **"不花哨"的判据**：位移 ≤12px、微反馈 ≤300ms、同时动起来的元素越少越好 —— 这些是**工程经验值，没有规范依据**。文档里要标注清楚，不要当成标准引用。
