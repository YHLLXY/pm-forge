## 0. 数据流全景（含后续开发兼容性，审查重点）

```
任务集 JSONL（公开，入 git）
   │  用户按任务卡在豆包/Kimi/DeepSeek 消费端手动逐条执行
   ▼
site/out/dissection-staging/<产品>/<taskId>/（原始粘贴+截图；gitignore，两步式第一态）
   │  AI 结构化为评测记录 JSON + 报告草稿
   ▼
用户通读全文（措辞纪律终审，章程 §6）
   │  显式拷贝
   ▼
site/src/content/dissections/（报告 md）+ site/src/content/dissection-records/（JSON 记录）
   │  zod schema（content.config）+ check-dissections.mjs（交叉校验）双重门禁
   ▼
/dissections/ 板块页面（schema 驱动渲染）→ 发布
```

- 依赖方向零破坏：全部在 site 模块内闭环 + evals 无交集；staging 在 out/（M4 先例，gitignore）。
- **与 B 线兼容（12 月）**：报告组件（T2）保持纯 props 接口，B 的 DuckDB-WASM 交互故事直接复用同一组件与 token；组件不内聚任何 A1 业务字段。
- **与 C 线兼容（寒假）**：C 走 vault-tools 发布管线（白名单+脱敏+链接重写），与 dissections 无共享文件，互不影响。
- **与 toolkitReports 无冲突**：evals 报告住 /toolbox/reports/，拆解报告住 /dissections/，两个集合两个 URL 空间，导航语义不混。
- **导航长期边界（审查补充，写死）**：B 线（12 月）是单页旗舰报告（spec §4 MVP 卡界），挂既有板块 URL 不加导航项；**后续新内容默认挂既有板块，导航只在出现真板块时动**——header 几何余量已近枯竭（复算见 T3），这条边界声明比任何一次性预案都重要。
- **staging 前提修正（审查 FAIL→已修）**：site/.gitignore 现无 out/（审查实测 git check-ignore 不命中；M4 的 out/ 先例属 vault-tools 模块）——T5 增加一步 `site/.gitignore` 追加 `out/`，两步式第一态才有 gitignore 护栏。

## 1. T1 · 评测记录 JSON schema + 双重门禁

**产物**：`site/src/content/dissection-records/*.json`（glob loader 数据集合）+ content.config.ts zod schema + `site/scripts/check-dissections.mjs`。

**记录 schema 字段**（spec §9.2 接缝 operable 化，每条实测一行）：

```jsonc
{
  "id": "doubao-write-001",           // <product>-<group>-<序号>
  "product": "doubao | kimi | deepseek",
  "group": "写作 | 检索 | 结构化产出 | 边界探测",
  "task": "一句话任务描述",
  "inputExcerpt": "输入摘录（合成任务，无隐私；≤200 字）",
  "outputExcerpt": "输出摘录（逐字，≤400 字）",
  "evalDate": "2026-11-03",           // 铁律 3
  "versionNote": "深度思考：开（入口：网页）",  // 版本口径，章程 §2.3
  "accountType": "免费",               // 章程 §3
  "scores": {                          // 复用 A2 rubric 四维；null = 本维度未评
    "factuality": 1-5|null, "structure": 1-5|null,
    "actionability": 1-5|null, "instruction": 1-5|null
  },
  "productMetrics": {
    "latencyTier": "快 | 中 | 慢",      // 体感分档（章程 §4）
    "paywallHit": false,                // 是否撞会员门槛
    "uxNotes": "改稿/追问/导出体验一句话或 null"
  },
  "verdict": "成功 | 部分 | 失败",
  "failureAnalysis": "verdict ≠ 成功 时必填（归因）",
  "screenshot": "文件名或 null"         // 截图文件名；原图留 staging 不入库
}
```

**zod 层**（构建即校验）：枚举字段、日期格式、scores 范围 1-5 或 null、verdict 枚举。
**check-dissections.mjs 层**（交叉不变量，入构建链；审查修正后语义）：①每条记录 evalDate + versionNote 非空（铁律 3 的机械执行）；②verdict≠成功 → failureAnalysis 非空；③**失败记录 ≥5 的生效语义 = 当 dissections 报告集合 ≥1 篇时才强制**（0 条目的章程先行阶段放行，先例 check-case-studies 对目录不存在放行）；④引号平衡检查**降级为 warning**（≤400 字截断摘录的截断点落在引号中间是合法形态，硬 fail 会误伤）；⑤隐私扫描**两层**：脚本内只放模式规则（手机号/证件号/上下文绑定的成绩数字模式，禁裸数字）入公开仓，真实人名等具体词表放 gitignored 私有文件（缺省跳过并打印"私有词表未加载"——**词表本身入库 = 把人名发布上网，恰是铁律 6 要防的事故**）；⑥文件名 === 记录 id 校验（glob loader 的 entry id 取自文件名，与 JSON 内 id 是两个东西）。

**单一数据源决策（审查补充）**：报告页指标由 records 聚合驱动（getCollection 按 product 过滤计算），**frontmatter 不放 metrics 汇总**——避免双源漂移；这同时落实 spec §9.2"报告页由 schema 驱动生成"。

**可行性**（审查已源码证实，spike 降级）：Astro 7 content layer 内置 .json data 条目（dist/core/config/settings.js:38-41、loaders/glob.js:95-107），glob+JSON 双集合可行；spike 只验证 entry id 生成与双集合 sync 细节。

## 2. T2 · 报告组件层（spec §7 首个落地）

**产物**：`site/src/components/reports/`——`ScoreBadge.astro`（1-5 分徽章，null 显示"未评"）、`DimensionBar.astro`（四维横条）、`VersionTag.astro`（日期+版本口径标注样式）、`RecordCard.astro`（单条实测记录卡：任务/输入输出摘录/判定/版本标注）、`FailureCallout.astro`（失败案例框：输入+实际输出+归因）。

**原则**：
- 纯 props 接口，零 A1 业务耦合（B 线直接复用的前提）；样式 token 全部走既有 CSS 变量（accent/border/muted/背景），新增 `src/styles/report-tokens.css` 只放报告语义 token（成功/部分/失败三色、分数梯度；**图表色板留待 B 线 spike 时补齐**——spec §7 要求 Observable Plot 同色板）；**实施时须在 global.css @import 该文件**（现有模式 global.css:2-3），漏挂 = token 全部失效。
- **对 spec 字面的有意偏差**：spec §7 说 design token 落 `shared/style/`——本轮先落 site 内，待 B 线报告形态出现第二个消费方时再做物理抽取（避免过早抽象，单消费方抽公共层是 YAGNI）。原则"三个报告形态一套视觉语言"通过"组件只依赖 CSS 变量"达成，B 线接入零改造成本。此偏差已在计划层记录，审查通过即为决策。

## 3. T3 · 板块骨架 + 导航几何预案

**产物**：content collection `dissections`（报告 md，frontmatter：product/productName/evalWindow/accountType/versionNote/tasksetRef/charterVersion/metrics 汇总）+ 三个页面：

1. `/dissections/`——板块首页：h1「AI 产品拆解」+ 一段定位语（"以实测记录回答一款产品的真实能力边界，不以印象回答"）+ **章程卡**（章程全文链接 + "评测章程先行"说明）+ 拆解报告列表（Card 复用）。**零条目态**：列表区显示"首篇拆解实测进行中（章程先行，2026-11 发布）"——这是真实状态陈述而非施工占位（对 #16 教训的针对性设计：0 条目时板块价值由章程卡承担）。
2. `/dissections/charter/`——章程 v2.0 全文（首发内容，随板块上线即发布）。
3. `/dissections/[slug]/`——单产品拆解报告页：概览卡（产品/账号类型/评测窗口/版本口径）+ 评分汇总（DimensionBar）+ 任务实测（RecordCard 按 group 分组）+ 失败案例库（FailureCallout）+ 边界能力清单 + 复盘。

**导航（审查 FAIL 复核后重写，方案待用户拍板——开工前必须定）**：审查员用源码真实值复算推翻了本计划初稿的全部三级预案：容器 max-w-app = max-w-3xl 768px − px-4×2 = **736px 内容宽**；现状 5 文字项 320px + 2 图标 64px + 6×gap-x-5 120px + 标题 ≈212px + ms-2 ≈ **724px，余量仅 ~12px**（与 E2 实测"第 6 个 47px 项必挂"吻合）。因此：加 48px 文字项（→792px）、第三个图标（→776px）、仅收间距（→~724-752px）**全部过不了 736px 线**；640 档（内容宽 608px）连现状都过不了，初稿门禁档位自相矛盾。**候选终局方案（四选一，待拍板）**：
- A（**✅ 2026-10-02 用户拍板**）：导航短标签——"案例研究→案例"、"数据分析→数据"省 64px，加"拆解"文字项，gap-x-5→gap-x-4，桌面断点 sm(640)→md(768)（<768 全走抽屉，抽屉任意条数安全）；估算 768 档 ≈665px < 736px，余量 ~70px。
- B：标题缩号 text-2xl→text-xl（省 ~35px）+ 全称标签保留 + gap-x-5→gap-x-3 + 断点后移；估算 768 档 ≈701px，余量 ~35px。
- C："拆解"图标入口（第三个图标）+ gap 收紧 + 断点后移；余量最小（~16-30px）。
- D："拆解"暂挂 /toolbox/ 子路径、零导航改动——与 spec"新板块"字面冲突，需用户豁免（板块页照建，只是入口在工具箱页内）。
- **无论选哪个**：几何门禁 = 768/1024/1280 三档全链接 h=32 单行 + 抽屉居中 0px + <768 走抽屉基线；不过不复测不打包。0 条目态文案**不带具体月份承诺**（"章程先行、首篇实测进行中"），防 T5 滑期后变成新的施工中谎言。

## 5. T5 · 实测执行协议（用户手动逐条，章程铁律 1-2）

**产物**：①`site/.gitignore` 追加 `out/`（**硬前提**，审查实测当前未忽略——没有这行，raw 全文与截图会以 untracked 暴露在 git status，两步式失去机械护栏）；②执行指引页（vault 私有，不上公开仓）；③staging 目录约定落**入库文档** evals/dissection/README.md（放 out/ 里的约定不进 git，跨会话失传）；④**发布用截图的入库路径 = site/src/assets/dissections/**（原图留 staging，报告引用的是入库副本），裁切规则：**不得出现本人账号昵称/头像/侧栏**（章程 §5 只排了他人信息，自己的账号信息同样不上公开站）。**收工判据（审查补充）**：本卡收工 = 前述四产物落库 + STATUS 更新；实测完成度由 T6 前置条件追踪，不算本卡验收。

- **路径**：`site/out/dissection-staging/<product>/<taskId>/raw.md`（复制的产品输出全文）+ `shot.png`（截图， charter §5 自截图规则）。
- **批次设计**：豆包 3 批（每批 4 条，30-45 分钟）、Kimi 1 批、DeepSeek 1 批——用户按自己节奏约时间，10 月中-11 月初完成。
- **每条记录**：任务原文照贴执行 → 输出全文复制存 raw.md → 关键状态截图 → 30 秒内记一行体感（延迟档/是否撞会员墙）。
- **纪律**：不批量、不脚本（铁律 2）；产品内可见版本信息/功能开关执行前先记 versionNote；额度提示原样记录。
- **本卡不做任何事，只产出协议文档与目录约定**——执行节奏完全由用户掌握。

## 10. 多视角自检（写计划时第一遍）

- **逻辑**：验收 ①-⑤ 逐条映射（§8）；"0 条目态"是对 #16 施工中教训的显式回应——板块上线日有真实内容（章程），不含谎言占位。
