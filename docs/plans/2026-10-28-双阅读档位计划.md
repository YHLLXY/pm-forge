# 2026-10-28 双阅读档位实施计划（简明 / 完整）

> 依据：`../research/2026-10-28-双阅读档位调研.md`（结论：机制成熟、两套文案不划算、推荐"一份正文 + 每节白话导读 + 深水块"）。
> 状态：**待用户拍板**（见 §8 三个决策点）。未拍板前不动代码。

## 1. 目标与非目标

**目标**
1. 一个只读 30 秒的读者，在任意案例页能看懂"这是什么、我做了什么、结果多少"。
2. 想深入的读者，一键（或一个链接）拿到全部技术细节，不丢内容。
3. 两种读法共用**一份事实**，任何数字只有一个出处。

**非目标**
- 不做"两篇独立文章"（除非用户明确要，成本见调研 §2-A）。
- 不改现有四段式结构与 12 道门禁的语义。
- 不做账号/服务端个性化（纯静态 + localStorage）。

## 2. 形态（方案 C）

每一节固定三段式：

```
<section data-section>              ← 由 rehype 插件按 ## 自动包裹
  <h2>三、过程与关键取舍</h2>
  <p class="lead">白话导读 · 40–70 字 · 必填</p>   ← 简明档显示
  <p>正文段落 ……</p>                              ← 完整档显示
  <div data-depth="deep"> … </div>                 ← 深水块，仅完整档
</section>
```

> 为什么要包 `<section>`：简明档要"只留导语、其余全藏"，靠 CSS 选择器 `h2 ~ p:not(:first-of-type)`
> 这种写法一遇到列表、引用、代码块就会漏。包成 section 之后规则只有一条：
> `[data-level="plain"] section > *:not(h2):not(.lead) { display: none }`。

- **简明档** = 每节导读 + 页头的事实条（metrics 已有）+ 结尾"结果与量化"的数字。
- **完整档** = 现在读到的全部内容。
- 两档共用同一份 DOM，切换只改 `<html data-level>`，**不重新请求页面**。

## 3. 分期

### P0 · 无开关版（最便宜的验证，3 h）

如果只想先看看"读起来是不是真的顺了"，可以先不做开关：

- 每篇开头加一个 **「30 秒版」** 块（3–5 句 + 3 个数字，纯静态，无 JS）。
- 每个 `##` 下加一段白话导读，**不隐藏任何内容**。
- 成本 ≈ 3 小时（2 篇），零状态、零闪烁、零 SEO 风险。
- 缺点：页面还是那么长，只是"开头就能看懂"。

**这一步就能验证核心假设**（导读写得好不好），而且不会白做——P1 的导读与它完全复用。

### P1 · 开关版（2 篇 + 基建）

| # | 任务 | 文件 | 验收 |
|---|---|---|---|
| 1 | 状态引导：inline 脚本同时设置 theme 与 level | `src/layouts/Layout.astro` | 首屏无闪烁；`html[data-level]` 在首帧就有值 |
| 2 | 开关组件：`简明 / 完整` segmented control | `src/components/ReadingLevel.astro` | 键盘可达、`aria-pressed` 正确、移动端不换行 |

同 P1 的第 4 项，逐篇补导读与深水标注；门禁已就位，只加内容。

数据分析 2 篇、AI 拆解 4 篇、工具箱报告 4 篇。这些板块的读者更专业，"简明档"收益递减——建议先看 P1/P2 的反馈再定。

## 4. 技术设计要点

### 4.1 状态与无闪烁

复用现有主题脚本的位置（`Layout.astro` 的 `<script is:inline>`），一次读两个 key：

```js
const level = new URL(location.href).searchParams.get("level")
  ?? localStorage.getItem("pm-level") ?? "plain";
root.dataset.level = level === "full" ? "full" : "plain";
```

- `?level=full` 可分享；进入页面后写回 localStorage。
- 与 `ClientRouter` 共存：换页时 `<html>` 不重建，属性天然保留。

### 4.2 组件

`ReadingLevel.astro`：两个按钮（`button[aria-pressed]`），点击写 `dataset.level` + localStorage，可选 `history.replaceState` 同步 URL。放在页头 `ThemeToggle` 左侧。

### 4.3 打印

`@media print { [data-level="plain"] section > * { display: block !important } }` —— 打印永远给完整版（面试官打印时不该丢内容）。

### 4.4 搜索

隐藏块加 `data-pagefind-ignore`。注意：pagefind 索引在构建期生成，属性必须写在 HTML 里（当前 pagefind 索引 29 页）。

### 4.5 Markdown 侧怎么标（关键实现选择）

内容还是 `.md`，不改成 MDX，避免作者写组件。用一个 **rehype 插件**（`src/utils/rehypeSections.mjs`，约 30 行）：

1. 按 `h2` 把 `<article>` 切段，每段包 `<section data-section>`。
2. 每段第一个 `<p>` 加 `class="lead"`。
3. 段内含 `<!-- deep -->` 注释的块（或约定前缀 `!!` 的段落）加 `data-depth="deep"`。

退路：如果不想写插件，就手写 `<div data-depth="deep">`（HTML 在 md 里可用），但导读的 `class` 还是要靠约定前缀 `▸ `，由插件或 CSS `::before` 处理——比插件丑，作为备选。

### 4.6 门禁 `check-levels.mjs`

断言（每条都能红）：
1. 每个 `<section data-section>` 必须有 `.lead`，且它是该段第一个段落。
2. 导读长度 20–80 字（中文按字符计）。
3. 导读里出现的数字（`\d+`）必须在该节正文里出现。
4. `data-depth="deep"` 里不得包含 `<h2>`/`<h3>`（否则简明档会丢标题层级）。
5. 每篇至少 2 个深水块（否则说明没做分拣，只是加了一段废话）。
6. 导读不得命中术语黑名单（注册中心 / 双适配器 / 幂等 / 编排 / 灰度 / evenodd）。

## 5. 导读写作规范（给文案用）

- 一句话说清：**谁**遇到**什么问题**，我**做了什么**，**结果多少**。
- 禁止术语黑名单：注册中心、双适配器、evenodd、幂等、编排、灰度……（首次出现必须解释或换说法）。
- 数字必须与正文一致，且带单位（3 天 / 13 个模块 / 26%–102%）。
- 不写"我学到了很多"这类无信息句。

示例（工作台，现状 → 导读）：

> 现状：**"模块注册表 + 双适配器数据层 + 三项体积预算，以及一套跑在免费额度上、每天自动出稿的 AI 日报链路。"**
> 导读：一个人用 10 周改了 47 个版本，把"今天要做什么"收进一个首页；为了让免费额度撑得住，每天自动生成一份 AI 日报。

## 6. 验收标准（数字）

| 指标 | 目标 | 怎么量 |
|---|---|---|
| 单页 HTML 增量 | < 8%（现 45–51 KB） | `dist` 文件大小前后对比 |
| 简明档页面高度 | 下降 ≥ 30% | 1440 下 `document.body.scrollHeight` |
| Lighthouse | 两页 ≥ 99，其余不降 | `npm run lh` |
| 切档无闪烁 | 0 次主题/档位闪动 | 截图对比首帧 |
| 键盘可达 | Tab 能到、空格/回车能切 | 手动 + CDP |
| 打印 | 恒为完整版 | `print-check.mjs` |
| 搜索 | 隐藏块不出现在结果里 | pagefind 查询隐藏段独有的词 |

## 7. 风险与回滚

| 风险 | 触发信号 | 回滚 |
|---|---|---|
| 导读写成"另一套说法"，与正文冲突 | 门禁第 3 条查不出语义冲突 | 导读只允许写正文里已有的句子/数字；争议时删导读 |
| 简明档太短，显得内容单薄 | 高度下降 > 70% | 减少深水块数量，保留结构性段落 |
| 维护负担 | P2 用时超过预估 2 倍 | 停在 P1，只在 2 篇上保留 |
| 与 ClientRouter 冲突 | 换页后档位丢失 | 用 `transition:persist` 或改读 `<html>`（本来就在 html 上，理论上不丢） |

回滚方式：删 `ReadingLevel.astro` + 去掉 `data-level` 样式，内容不动（导读段落退回普通段落，不影响阅读）。

## 8. 待用户拍板

1. **默认档位**：`简明`（推荐）/ `完整` / 跟随上次选择（首次访问给哪个）。
2. **范围**：只案例（P0+P1+P2，约 11–15 h）/ 再加数据分析与拆解（P3，共约 19–27 h）。
