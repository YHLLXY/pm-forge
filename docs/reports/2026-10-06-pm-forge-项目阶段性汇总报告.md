## 1. 项目是什么

**pm-forge 是一个面向 AI 产品经理求职的作品集工程**：不是"作品集页面"这一个静态物，而是一条把真实工作方式展示出来的流水线——数据要能复算、结论要能溯源、质量要有门禁、发布要走流程。它服务的主线是 2027 秋招的 AI PM 面试五考点，各板块与考点映射：

| 板块 | 面试考点 | 作品集主张 |
|---|---|---|
| M1 分析线 | 数据分析能力 | 同一份数据，SQL/pandas 双实现交叉验证，口径可查 |
| A2 工具箱 | AI 落地与评测 | 不只"会用 AI"，而是给 AI 建了评测集与回归基线 |
| A1 拆解 | 模型评估与伦理风险 | 手动逐条实测消费级 AI 产品，失败案例与成功案例同等呈现 |
| B 数据故事 | 数据叙事 + 前端工程 | 读者在浏览器里亲手复算作者的数据（DuckDB-WASM） |
| C 隐私写作（寒假） | 工程判断与合规 | 键控消歧设计——待启动 |

## 2. 资产全景（按线盘点）

### 2.1 M1 数据分析线（最早完成）

- UserBehavior（淘宝公开数据集）100k 行 reservoir 抽样（seed=42）的完整分析管道：`analysis/src/pmforge_analysis/`（ingest / metrics / funnel / rfm）。
- 沉淀了数据口径的"宪法"：官方窗口清洗（`clean_window`，ISSUES #5 记录的脏时间戳处理）、UTC+8 墙钟语义。B 线后来整个复用了这套口径——**先有口径宪法，后有复用**，这是 M1 最有长期价值的部分。

### 2.2 A2 工具箱线（AI 工具 + 评测体系）

- **产品**：toolkit/（Next.js）三个真实可用的 AI 工具——竞品分析、用户反馈洞察、PRD 草稿，部署于 toolbox.yuhailinlxy.com，API live 模式（DeepSeek 底座，key 只在服务端环境变量）。
- **评测体系**（`evals/`）：66 例三工具评测集（含 JSONL 数据集、rubric 四维评分、judge 模型 deepseek-flash 温度 0）、基线 run 20260930-005223、结构检查器（JSON 合法/数量守恒/引用逐字/枚举合法）。
- **一次完整的产品迭代**：基线评测抓到 4 例契约违例 → 归因三分类（2 真缺陷/1 契约过严/1 检查器级联误报）→ 修复三件套（prompt v1.1、服务端校验+重试、契约放松）→ 复测 66 例结构检查全 100%。全程有报告：《AI 工具箱 evals 基线报告》《评测驱动的第一次产品迭代》。
- **报告层**：`site/src/content/toolkit-reports/` 共 6 篇（3 篇工具报告 + evals 计划 + 基线报告 + 契约修复报告），RSS 收录。

### 2.3 A1 拆解线（2026-10-06 已上线）

- **章程先行**：`docs/specs/2026-10-02-pm-forge-A1拆解评测章程.md` v2.1——六条铁律（自有数据/手动逐条/日期版本留痕/措辞纪律/时效声明/隐私红线）+ v2.1 执行授权修订款（AI 协作者人工节奏代跑 + API 逐条不算规模自动化）。
- **实测资产**：30 条评测记录 JSON（豆包 14 / Kimi 6 / DeepSeek 10，23 成功 / 2 部分 / 5 失败，失败案例库 ≥5 达标）、任务集 27 条（14+6+7，含陷阱探测、顺从性探测）、20 张截图全部脱敏（`sanitize-shots.mjs`）。
- **三篇拆解报告**：豆包主评（边界诚实 + "最近邻桥接"幻觉）、Kimi 对照（长文本）、DeepSeek 对照（一开关两种命运：chat/reasoner 双模式）。全部走两步式发布（staging → 代行措辞终审 → 构建 → 上线）。
- **组件层**：`site/src/components/reports/` 五组件（RecordCard / DimensionBar / ScoreBadge / VersionTag / FailureCallout）+ report-tokens.css——B 线直接复用同一套视觉语言，验证了"报告组件层"一次建设多处复用的设计。
- **有复用价值的发现**（写进报告的）：DeepSeek 的自查只在"答案内部数字互斥"时触发，对外部权威压力不设防——厘陷阱与顺从性投降两案同源；豆包会用专家口吻把不存在的实体无缝桥接到真实知识上。

### 2.4 B 数据故事线（2026-10-06 一日贯通并上线）

- **页面**：`/data-stories/userbehavior/`——《淘宝用户行为九日谈：一场浏览器里的复算》。7 节滚动叙事（≥5 达标）、10 个预置问题（3 大数字卡 + 7 张 Observable Plot 图，进视口才加载）、桌面端受限查询框（白名单 SQL 拼装：行为/类目/日维度 × 行为筛选 × 指标 × limit 1-50 × 日期区间，零自由文本进 SQL）。
- **架构决策**（均为实测驱动）：DuckDB-WASM EHDR 单线程形态（免全站 COOP/COEP 头）、懒加载唯一入口 `duckdb-loader.ts`（点击才拉 33MB 引擎）、SQL 拼装唯一收口 `allowed-queries.ts`、移动端降级（视口+触控判定，表单整体移除、绝不加载 WASM）、跨端时区用纯整数墙钟运算（ts+28800 对 86400 取模）。
- **口径一致性链**：Python 预生成（`precompute_story.py`）↔ 浏览器查询（loader 视图同窗）↔ pandas 交叉验证（`check_story_presets.py` 逐值比对）↔ 页面叙事数字逐值溯源。99,958 行（100k 清洗后）是全链唯一口径。
- **门禁**：体积门禁（dist 产物实测：duckdb 33.39/40MB、数据 2.03/3MB，超限 fail 已反向验证）+ Playwright 双门禁 `check:story`（场景 1 桌面首屏滚动零重资源；场景 2 移动端零重资源+降级提示在位；场景 3 引擎冒烟行数钉死口径；`--reverse` 内置反向自检）。

### 2.5 工程底座

- **构建链**（site）：`copy-duckdb-assets → astro check → astro build → check-case-studies → check-dissections → check-links → validate-rss → check-ld → check-story-budget → pagefind`，任一环 fail 即断链。
- **流程纪律**：两步式发布（staging → 终审 → 显式拷贝 → 构建 → 发布）、显式 git add（禁 -A）、commit 前缀（feat/fix/docs）、每 commit 必 push、里程碑间一周缓冲、12 月考试季冻结。
- **经验库**：docs/lessons-learned.md 累计 10+ 条（Astro 表达式容器禁语句 ×2、管道退出码 ×2、tsconfig 大二进制爆堆、Astro 7 preview 单例锁、DuckDB 跨端时区、幂等重生成查非确定性等），并同步进 AI 协作者长期记忆。

- 每个板块对应一个考点，且都有"超出会用"的证据：评测集与基线（不是 vibes）、失败案例库（不是选择性展示）、口径标注（每个数字有定义）、门禁（质量是流程不是口号）。

**开发者/未来的自己视角**：
- 口径改一处（窗口、时区、抽样）会被至少三道机械检查拦住（幂等重生成 diff、pandas 逐值比对、引擎冒烟行数）。
- 一条命令验证整站：`npm run build`（含全部门禁）+ `npm run check:story` + `uv run python -m pmforge_analysis.check_story_presets`。

### 5.2 B 线的演进空间（next 1-2 天可做的）

- **查询维度扩展**：category_id 维度目前 Top-N 可查，item_id / user 级留存（RFM）维度未开放——白名单机制已就绪，加枚举即扩（注意 limit 与聚合口径）。

### 5.3 A1 线的演进空间（11 月窗口）
