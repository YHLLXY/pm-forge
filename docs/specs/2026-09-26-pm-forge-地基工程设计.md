## 2. 总体架构

### 2.1 目录结构（monorepo，方案 B）

```
E:\homework\开发\pm-forge\
├── site/          # M3 作品集站点：Astro 5 + React 岛屿 → Vercel
├── toolkit/       # M2 AI PM 工具箱：Next.js 15 + React 19 Web 应用
├── analysis/      # M1 数据分析：uv + Jupyter/Quarto + DuckDB
├── vault-tools/   # M4 知识库自动化：Python 只读巡检脚本
├── shared/
│   ├── templates/ # PRD / 竞品分析 / 复盘 模板（md，来源见 3.2）
│   └── style/     # 跨模块视觉规范（色板、字体、组件约定）
├── docs/
│   ├── specs/     # 本文件及后续设计文档
│   ├── plans/     # writing-plans 产出的任务卡
│   ├── STATUS.md  # 跨会话进度交接（AI 连续工作协议核心）
│   ├── ISSUES.md  # 问题登记（按 AGENTS.md 12.5）
│   └── lessons-learned.md
├── AGENTS.md      # 本仓 AI 协作准则：继承用户 vault AGENTS.md v2.4 全部红线 + 仓库特化规则
└── README.md      # 含更新日志与文件结构（AGENTS.md 13.4）
```

### 2.2 依赖方向（单向，禁止循环）

```
analysis ──产出报告(md)──→ site/content
toolkit  ──产出报告/演示──→ site/content
shared/templates ──被引用──→ toolkit / analysis / site
vault-tools ──只读 E:\knowledge home──→ 报告输出至 vault/91-MOC（不经 site）
```

模块间只通过文件与公开接口交互，禁止 import 其他模块内部实现。单文件超 500 行强制拆分（AGENTS.md 11.3）。

### 2.3 技术栈总表（选型依据全部来自 08/09 号调研）

| 层 | 选型 | 依据（08/09 号调研） |
|---|---|---|
| 作品集站 | **Astro 5 + React 岛屿**，模板基底 AstroPaper（约 5.1k star） | 08 号：内容站 2026 共识 Astro 胜出（零 JS、Lighthouse 高 40-60%），React 岛屿复用存量技能；用户已确认 Astro |
| 工具箱 | **Next.js 15 + React 19**（Web 应用，非 CLI） | 08 号：乔木 App 洞察（223 star，同栈）验证了该模式；Web 形态对 PM 面试演示远胜 CLI；复用用户 React/Supabase 存量 |
| LLM 接入 | OpenAI 兼容接口 + 可配置 base_url，默认 DeepSeek/GLM（国产直连） | 08 号第 5 节：规避国内访问风险；用户现成渠道 |

| vault 自动化 | **obsidiantools（Python 库）自写巡检脚本**；obsidian-git 作 vault 备份保底；obsidian-local-rest-api（内置 MCP）列为 P2 演进项 | 09 号第 4 节 |

## 3. 模块规格

### M0 工程地基（一切之前）

- **目标**：仓库、准则、模板三件套就位。
- **范围**：init git（SSH 远端 `git@github.com:<用户>/pm-forge.git`）；写 AGENTS.md（继承 vault v2.4 全部红线：变更前征得同意/禁止猜测/显式 add/禁 add -A/commit 前缀/默认 push/README 同步 + 仓库特化：模块边界、token 预算、任务卡协议）；`shared/templates/` 落 8 份模板（来源：tianma-if/awesome_product_design 的 PRD/竞品分析/复盘模板，08 号调研已核实）+ 自建"案例分析模板"（按 08 号核实的四段式：背景问题→我的角色→过程取舍→量化结果）；README 含结构与日志。
- **验收**：clone 到空目录后按 README 可复原开发环境；AGENTS.md 含全部红线条目；8+1 份模板就位；首次 commit+push 成功。

### M1 数据分析工程（先建，原料厂）

- **目标**：建成"一个数据集吃透一条链"的分析流水线，产出可发布的产品分析报告。
- **范围**：uv 项目初始化（ruff/pytest/pre-commit）；DuckDB 本地查询环境；数据获取脚本（天池 UserBehavior 下载+抽样 10 万行，脚本化可重跑）；案例一"电商用户行为指标树"（OSM+AARRR 指标体系 → 漏斗 → RFM 分层，方法论文档见 09 号调研第 1 节）；Jupyter 探索 → Quarto 出报告 → 报告 md 发布进 site/content。
- **不做**：机器学习建模、实时数据、大数据组件（Spark 等）。
- **验收**：① 一条命令可复现全链（取数→清洗→指标→图表→报告）；② 报告含至少 8 个有口径定义的指标；③ pytest 覆盖数据清洗与指标计算函数；④ 报告在 site 本地预览可见。

### M2 AI PM 工具箱（Next.js Web 应用）

- **目标**：可演示、可分享的 AI 产品分析工具站，作品集的"明星项目"。
- **范围（v1 三工具）**：`竞品分析`（输入产品名/描述 → LLM 结构化五维对比 → 证据链标注的报告）；`用户反馈洞察`（粘贴/上传评论 CSV → LLM 主题聚类 → 优先级矩阵）；`PRD 草稿`（模板驱动 + AI 填充，模板来自 shared/templates）。
- **架构模式**：复刻 08 号调研提炼的五层模式：采集→缓存→LLM 分析→证据链→产出。LLM 层 OpenAI 兼容 + base_url 可配（.env，DeepSeek/GLM 切换）。参考实现：乔木 App 洞察（同栈）；功能规格参考 phuryn/pm-skills（约 26.6k star）选取 3 个技能。
- **不做（v1）**：用户系统、数据库持久化（Supabase 列 P2）、爬虫、流式协作编辑。
- **验收**：① 三工具全可用，vitest 单测 + 每工具至少 1 条端到端用例；② 每个工具用真实输入产出 1 份报告并发布进作品集（工具自证）；③ LLM 调用有 token 估算与上限守卫（单次请求超预算需显式确认）；④ 部署 Vercel + 自定义域名可访问。

### M3 作品集站点

- **目标**：面试时直接甩链接的"数据驱动产品候选人"门面。
- **范围（五板块）**：首页（定位一句话+精选）；案例研究（存量资产产品视角重写：AgriAgent 小挑、个人工作台、couple、红岩网校落选复盘——写成"产品复盘型案例"，08 号调研建议）；数据分析（M1 喂养）；工具箱（M2 喂养+在线演示入口）；关于（简历+群面方法论小史）。
- **部署**：Vercel + 自定义域名 + Cloudflare DNS（用户侧操作项见第 7 节）。
- **里程碑**：2027 寒假第一版上线 → 每月迭代 → **2027-08-31 定稿**。
- **验收**：① Lighthouse 移动端 ≥90；② 每篇案例过四段式结构与"量化结果"检查；③ 国内直连可打开（自定义域名）。

### M4 vault-tools 知识库自动化

- **目标**：消灭 2026-09-25 事故源（148 篇零入链散点），建立巡检三件套。
- **范围**：Python + obsidiantools 只读扫描 `E:\knowledge home`：① 孤立节点检测（按全路径消歧，AGENTS.md v2.4 要求）；② 索引完整性校验（目录文件 vs _Index 条目双向 diff）；③ 体检报告（输出 markdown 至 vault/91-MOC，遵循 source: claude 标注）。
- **不做**：任何对 vault 的自动写入/修改/删除；obsidian-local-rest-api MCP 接入列为 P2（届时单独设计）。
- **验收**：① 三脚本 pytest 全绿（用 vault 的测试夹具目录）；② 对当前 vault 跑一遍，产出体检报告且用户确认结果与 Obsidian 图谱观感一致；③ 运行不修改 vault 任何文件（git status 验证）。

## 4. 工程规范

### 4.1 Git（继承 AGENTS.md 13 节全部规则）

显式 add 禁 add -A；SSH 推送；`feat:/fix:/docs:/style:/refactor:` 前缀；commit 必须同 commit 更新 README；默认 push。两个子项目（site/toolkit）在 monorepo 内独立目录、共享一个仓库，Vercel 各建项目分别指定根目录。

### 4.2 测试与质量

toolkit 用 vitest + Playwright 端到端；analysis/vault-tools 用 pytest；site 用 `astro build` 作构建校验。推送前 diff 自审（AGENTS.md 12.3 五维度）。No completion claims without fresh verification evidence（AGENTS.md 12.2）。

### 4.3 AI 连续工作协议（核心创新，服务"长时间连续工作"）

1. writing-plans 产出任务卡文件（`docs/plans/YYYY-MM-DD-<主题>.md`），每卡 ≤1 天工作量、含验收 checkbox。
2. 每次会话开始：读 `docs/STATUS.md` + `AGENTS.md` + 当前任务卡 → 领下一张卡。
3. 每次会话结束（无论是否完成）：更新 STATUS.md（做了什么/决策/遗留）+ commit + push + 按 AGENTS.md 第十/十六节沉淀经验到 vault。
4. vault 侧同步按第十八节收口自检（双向 diff / 零入链=0 / 刻意不连写明）。

### 4.4 Token 预算与安全

toolkit 每类 LLM 请求设 token 上限估算守卫；开发期调试用最小输入；API key 一律 .env（.gitignore 首行），**永不入库**；数据集大文件不入 git（gitignore data/）。

### 4.5 国内网络纪律

GitHub 仅 SSH；npm/pnpm 用 npmmirror；模型 API 用国产直连；Vercel 部署正常但访问必须走自定义域名。
