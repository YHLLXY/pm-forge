## 摘要

1. **右栏宽度高度收敛**：四家右栏实体实测 **240 / 250 / 250 / 265px**（Vercel / Stripe / Josh / Astro 右侧栏内层 nav）；MDN 的 `<aside>` 外壳是 **297px**，但其内部真正放目录的 `nav` 只有 **169–181px**。**结论：右栏实体宽度的主流区间是 240–265px；带内边距的外壳可以到 297px。【官方源码】**
2. **没有任何一家用竖线分隔右栏**：五家右栏 `border-left` 全为 `0px`。间距靠三种手法之一：① grid `column-gap`（Josh 100px、MDN 32px、Vercel 68px）；② 右栏自身 `padding-left: 48px`（Stripe）；③ flex 的 `mr-4` + 容器余量（Vercel 的 Tailwind 类）。**唯一用线的是 Linear 的左侧主导航** `border-right: 1px solid rgb(35,37,42)`。【官方源码】**
3. **目录项字号一律比正文小**：Stripe 14px（正文 16px）、Vercel 14px（正文 16px）、Astro 13px（正文 16px）、Josh 16/14px（正文 18px）、MDN 16px（正文 16px，**唯一不弱化的例外**）。**主流是 13–14px。【官方源码】**
4. **当前项高亮有三派，都成立**：① **只变色**——Astro 右栏目录当前项实测 `color: rgb(61,80,245)`，`font-weight` 仍是 400；② **变色 + 加粗**——Stripe 右栏的首个目录项实测 `color: rgb(84,105,212)` + `font-weight: 500`，其余项为 `color: rgb(26,44,68)` + `font-weight: 400`；③ **变色 + 左侧竖条 + 背景块**——MDN 原文 `[aria-current="true"]:is(.reference-toc a) { background-color: var(--color-area-background); box-shadow: -2px 0 0 var(--color-area-highlight-border); }`。**竖条用 `box-shadow: -2px 0 0` 而不是 `border-left`，这是 MDN 的原话。【官方源码】**
5. **Josh W. Comeau 的目录没有当前项高亮**：滚动到 45% 后在右栏内检索 `[aria-current],[class*=active],[class*=current],[data-active]` 命中 **0** 条。它的层级只靠 `opacity: 0.7`。【官方源码】
6. **十家真实站点全部没有阅读进度条，也没有「回到顶部」**：对 `progress|reading-time|scroll-indicator` 与 `back-to-top|to-top|scroll-top` 的检索结果在 10 个站点上**全部为空数组**。**不做这两样是主流，不是偷懒。【官方源码】**
7. **只有 MDN 给右栏设了高度上限**：`max-height: calc(100vh - var(--sticky-header-height)); overflow-y: auto; position: sticky; top: var(--sticky-header-height)`（实测 `top: 98px`、`max-height: 802px`）。其余四家是 `max-height: none` + `overflow-y: visible`。【官方源码】**
8. **sticky 的 `top` 实测四档：56.5 / 88 / 98 / 160px**（Stripe / Vercel / MDN / Josh）。规律是「自身固定头部高度 + 0~64px 呼吸」——**它必须由本站头部高度反推，不能照抄数字**。【官方源码】
9. **移动端退化三种做法**：① 整块 `display:none`（Josh `@media (max-width: 66.5rem)`；Vercel `hidden lg:block`）——**一行 CSS、零风险，最贴合本项目「<1024px 一行都不变」的硬约束**；② 塌进正文流（MDN `@media (width < 50rem){position:unset; top:unset; max-height:unset; overflow-y:unset}`；Astro 在 390px 变成 w=358、x=16 的静态块）；③ 抽屉/覆盖层（Stripe、Vercel 的左侧栏）。【官方源码】
10. **本项目几何已复测，与既有结论一致**：容器 `.app-layout` **1120px**（视口 1440 时 x=160），`padding-inline: 16px` → 内容盒 **1088px**；正文 `.max-w-readable` **638px**（x=176，右边缘 814），**16px / 行高 28px**，正文色 `rgb(28,27,26)`。正文右边缘到容器**外缘**的空档 = **466px**，到**内容盒右缘** = **450px**——**450px 正好够放「64px 间距 + 240px 右栏 + 146px 余量」，即方案 B 可落地且不必改容器宽度。【本项目实测】**

### 一、能用的（按价值排序）

| # | 来源 | 规则 | 为什么能用 |
|---|---|---|---|
| 1 | Vercel Docs 的 aside 类名 | `w-[240px] max-w-[240px] shrink-0 order-last sticky top-[var(--…)] hidden lg:block` | 这几乎就是我们需要的全部形态：定宽、不收缩、sticky、**大屏才显示**。`hidden lg:block` 天然满足「<1024px 一行 CSS 都不变」——右栏在移动端根本不参与布局。Tailwind v4 里可以直接写等价类。 |
| 2 | MDN | `box-shadow: -2px 0 0 var(--color-border-primary)` 做左侧竖条 | 不占布局宽度（border 会撑开盒子）、不触发重排、颜色可随状态切换。**当前项换色也只需改 box-shadow。** |
| 3 | MDN | `max-height: calc(100vh - <顶部偏移>); overflow-y: auto; position: sticky; top: <顶部偏移>` | 五家里唯一给右栏设上限的做法。我们的工具箱报告 h2 达 8 个，**不设上限的右栏在长文里会一直停在顶部、失去「跟随」意义**；设上限后退化为内部滚动，最稳。 |
| 4 | Josh W. Comeau | `text-transform: uppercase; letter-spacing: 2px` 做区块标题；目录项 `opacity: 0.7` | 「大写 + 字距」做标签，**零边框、零背景**就能建立层级，最符合「克制、暖色」的调性。中文不适合 uppercase，但**「小字号 + 加字距 + muted 色」等价且成立**。 |
| 5 | Stripe Docs | 三级字号 13 / 14 / 12px | 给出了「区块标题 / 目录项 / 次级注释」三档的相对关系；我们的正文 16px，取 12 / 14 / 12px 与之同构。 |
| 6 | Stripe Docs / Josh | 右栏自身 `padding-left` 或 grid gap 提供间距，**`border-left: 0`** | 五家右栏 `border-left` **全部为 0**。加竖线是反主流、且会额外增加一条视觉线（我们页面已有 `--border: #e6e2db` 的大量使用，再加一条会更花）。 |

| 9 | Stripe / Vercel / Josh | 当前项「变色」或「变色 + 加粗」 | 两种都在一线站点成立。**中文标注建议只变色 + 左侧竖条，不加粗**——因为中文字重变化在小字号下容易糊（且我们自托管字体的可用字重未知，需先确认）。 |

### 二、不能用的 / 不建议照抄的

| # | 来源 | 为什么不能用 |
|---|---|---|
| 1 | 设计灵感站（Awwwards / Behance / Mobbin / Land-book / siteInspire / Minimal Gallery / One Page Love）的栅格 | 它们是 **2/3/4/12/16/32 栏的卡片墙**，服务「发现」；我们是**单篇消费型长文**。**方法论不可迁移**，只有「卡片比例」这类信息，与右栏无关。 |
| 2 | Starlight 的 `width: max(var(--sl-sidebar-width), calc(var(--sl-sidebar-width) + (100% - var(--sl-content-width) - var(--sl-sidebar-width)) / 2))` | 代入我们的数字会得到 `max(300, 300 + (1088−638−300)/2) = 375px` —— **太宽**。这个公式的前提是正文列 720px（45rem），而我们只有 638px。**不能照抄公式，只能照抄思路。** |
| 3 | MDN 的目录项 **16px / 与正文同字号同色** | 英文 16px 短标签没问题；我们的 h2 是**中文长句**（最长 203px @13px），16px 会到约 250px，240px 的栏放不下，必然折行成两行，目录立刻变高变乱。**必须降字号。** |
| 4 | Josh 的 `@media (overflow:clip) { position: sticky }` | 这是 Josh 为他自己的祖先 `overflow` 结构写的**防御性条件**。直接抄会让我们在无意间失去 sticky。**只抄 `position: sticky; top: <值>`，不要抄这个条件。** |
| 5 | Stripe 的 `padding-left: 48px` 提供间距 | 只有在我们**完全不设 grid gap** 时才等价；而且 48px 会吃掉栏内宽度 —— 我们 240px 的栏扣掉 48px 只剩 192px，**放不下 203px 的中文标题**。要抄就抄它的**动机**（零竖线），实现上用 grid gap。 |
| 6 | Linear 的 `border-right: 1px solid` | 那是**左侧主导航**的分隔方式，不是右栏信息栏。右栏五家样本里 0 个用线。 |
| 7 | Tailwind Docs 的 `grid-cols-subgrid` + `lg:col-start-3` | 需要父级已经是多列栅格；我们详情页目前是单列流式布局，没有父栅格可 subgrid。**除非重构成整站栅格，否则用不上。** |
| 8 | 阅读进度条 / 「回到顶部」 | **10 个真实站点 0 个做**。它不违反我们的任何硬约束（可以纯 CSS + 极少量 JS 实现），但**它不是行业标配，做它是加分项、不是必答题**；而且进度条大多要 `position: fixed` 覆盖层，会引入新的层叠与移动端遮挡风险。**建议本期不做。** |
| 9 | Vercel 右栏当前项的**精确**样式 | **【未核实】**（见 2.4）。不能拿 `rgb(235,235,235)` 背景块当作它的右栏样式——那个实测值来自 `x=4` 的**左侧**导航。 |

### 三、可直接落地的三套方案

**共同前提（三套都一样，已实测可成立）**
- 断点：`@media (min-width: 1024px)` —— 与既有方向一致。**<1024px 不生成任何右栏布局，正文列完全不动，满足「移动端一行 CSS 都不变」。**
- 不新增第三方请求：目录在构建期由 Astro `render()` 的 `headings` 生成（实测 `headings[].slug` 与 `<h2 id>` 一致），**零运行时请求**。
- CLS：`position: sticky` 不产生布局位移；右栏在 `<1024px` 为 `display: none`（不参与布局）。**sticky 元素本身不改变任何已有元素的几何**，满足 CLS=0。
- 「当前项」若要做，用 `IntersectionObserver` + `aria-current="true"`（MDN 的做法，实测其当前项带 `aria-current="true"`），内联脚本、无依赖。
- 分隔线：三套**都不给右栏加 `border-left`**（五家实测全为 0）。
- 隐藏滚动条问题：右栏若 `overflow-y: auto`，需配 `scrollbar-width: thin` 或将 `top` 与 `max-height` 配套设好，避免双滚动条。

---

#### 方案 A｜零位移加法（最保守）

> 定位：**正文列 x 坐标一像素都不动**。适合「怕影响存量排版」的路线。

- **结构**：`grid-template-columns: minmax(0, 68ch) 240px; column-gap: 48px; justify-content: start;`
- **几何（实测推算）**：正文仍在 x=176、宽 638px；右栏 x = 176+638+48 = **862 → 1102**；容器内容盒右缘 1264 → **右侧余 162px**。整组明显偏左。
- **栏宽**：**240px**（= Vercel 实测值）
- **字号**：区块标签 **12px / line-height 1.4 / letter-spacing 0.08em**；目录项 **13px / line-height 1.5**；次级注释 **12px**
- **颜色层级**（全部用现有 token，见 `theme.css:30-53`）：
  - 区块标签 → `text-muted-foreground`（`#6b655c`）
  - 目录项（未选中）→ `text-foreground/70`（`#1c1b1a` 的 70% 透明度，**逐字对应 Josh 的 `opacity: 0.7`**）
  - 目录项（当前）→ `text-accent`（`#0b6bcb`）
- **分隔方式**：**无竖线**，仅 48px 留白
- **目录项样式**：`display: block; padding-block: 6px; padding-left: 10px;`
- **当前项高亮**：变色 + 左侧 2px 竖条
  ```css
  /* 竖条用 box-shadow，逐字照抄 MDN 的技法 */
  [aria-current="true"] { color: var(--accent); box-shadow: -2px 0 0 var(--accent); }
  ```
- **sticky**：`position: sticky; top: <头部高度 + 24px>;`（实测锚点 56.5/88/98/160px，**必须按本站头部实测值反推**）
- **取舍**：正文零风险，但**整组重心偏左 162px**，视觉上会显得「左边一坨、右边空一块」。

---

#### 方案 B｜居中双列（**推荐**）

> 定位：把「正文 + 间距 + 右栏」当成**一个整体居中**，这是 MDN / Starlight 呈现出的对称感，也是 1120px 容器下最平衡的解。

- **结构**：`grid-template-columns: minmax(0, 68ch) 240px; column-gap: 64px; justify-content: center;`
- **几何（实测推算）**：组宽 = 638 + 64 + 240 = **942px**；内容盒 1088px → **左右各余 73px**；正文左边缘 176 → **249（右移 73px）**；右栏 **x=951 → 1191**。
- **栏宽**：**240px**
- **字号**：同方案 A（12 / 13 / 12px）
- **颜色层级**：同方案 A
- **分隔方式**：**无竖线**，64px 留白（落在实测 32–100px 区间内）
- **目录项样式**：`display: block; padding-block: 8px; padding-left: 10px;`
- **当前项高亮**：变色 + 左侧 2px 竖条（同方案 A 的 `box-shadow`）
- **栏高上限**：推荐直接上 MDN 的做法
  ```css
  position: sticky;
  top: calc(var(--app-header-h, 64px) + 24px);
  max-height: calc(100vh - var(--app-header-h, 64px) - 48px);
  overflow-y: auto;
  ```
- **取舍**：正文右移 73px —— **这是本方案唯一需要你拍板的地方**。它换来的是整页对称；如果「正文 x 不许动」是硬要求，就退到方案 A。
- **为什么推荐**：① 450px 余量刚好被 64+240+146 消化，**不用改 1120px 容器、不用改 68ch 正文**；② 240px 与最长中文标题 203px 的关系是「刚好放得下」，配合 13px 字号单行成立；③ 全部 token 都是现成的。

---

#### 方案 C｜居中 + 宽栏三段式（280px）

> 定位：给「目录 + 本篇信息 + 快速跳转」**三段内容**留出真正够用的宽度。

- **结构**：`grid-template-columns: minmax(0, 68ch) 280px; column-gap: 64px; justify-content: center;`
- **几何（实测推算）**：组宽 = 638 + 64 + 280 = **982px** → **左右各余 53px**；右栏 **x=911 → 1191**。
- **栏宽**：**280px** —— 最长中文标题 203px 放进去后还剩 77px 余量，**能容纳 14px 字号的目录项**（14px 时该标题约 219px，240px 栏放不下、280px 栏刚好）。
- **字号**：区块标签 **12px / letter-spacing 0.08em**；目录项 **14px / line-height 1.6**；次级注释 **12px**
- **颜色层级**：同方案 A/B
- **分隔方式**：**右栏不加竖线**；三段之间用 **`border-block-start: 1px solid var(--border)`**（`#e6e2db`）分隔
- **"本篇信息"块用卡片**（逐字照抄 Astro 右栏卡片的思路）：
  ```css
  border: 1px solid var(--color-border);       /* Astro: 1px solid var(--sl-color-gray-5) */
  background-color: var(--color-surface-2);    /* Astro: var(--sl-color-gray-6) */
  border-radius: 0.5rem;                       /* Astro: 0.5rem */
  padding: 16px;                               /* Astro 实测: 16px */
  ```
- **当前项高亮**：变色 + 左侧 2px 竖条（同 A/B）；因为栏更宽，**可选**叠加浅底色块（MDN 实测 `background-color: rgb(236,244,254)`，我们对应 `--muted: #f0ede8`）
- **sticky / 栏高上限**：同方案 B
- **取舍**：栏更宽、字号更大、三段内容舒展；代价是正文右移 73px（同 B），且 **280px 会让右栏视觉重量上升**——需要靠「字号小 + 颜色弱 + 无边框」压住，否则会跟正文抢注意力。
