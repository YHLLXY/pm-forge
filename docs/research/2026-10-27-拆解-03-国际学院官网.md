- 日期：2026-10-27
- 对象：<https://international.cqupt.edu.cn/>
- 方法：CDP 直连无头 Edge（1440×900 / 390×844）+ 静态保存 HTML 与 12 个 CSS 包

## 0. 结论先行

**它是一套"读者分层 + 列表密度"做得对、但视觉与工程停在 2015 年的政务站。**

值得学的只有两件：**按"读者是谁"组织导航**，以及**"日期 + 标题 + more>>" 的高密度可扫读列表**。美术与动效没有可学之处，但它把"信息量"这件事做到了位。

| 维度 | 判断 |
|---|---|
| 信息架构 | ★★★ 8 个一级栏目按"考生/在校生/教师/国际生"分层，首页再做 6 个快捷入口 |
| 列表密度 | ★★★ 招生信息 4 条 + 就业信息 2 条 + 新闻 5 条，一屏给足 |
| 视觉系统 | ★ 方角、灰底按钮、10px 根字号、无字号阶梯 |
| 工程 | ★ 32 个 script、3 套 UI 库并存、外链 iconfont、AOS 无降级 |
| 无障碍 | ★ 导航项用 `h3`、无 `:focus-visible`、无 `prefers-reduced-motion` |

## 2. 信息架构：按"读者"而不是"内容类型"分

主导航 8 项：

```
首页 · 学院概况 · 学院动态 · 教育教学 · 师资队伍 · 招生就业 · 学生事务 · Study@CQUPT
```

首页的信息密度（一屏 1503px 内）：

| 区块 | 内容 | 高度 |
|---|---|---|
| 头部 | 院徽 + 书法体院名图（`college_title.png`）+ 8 项导航（当前项橙底白字） | 192px |
| 新闻区 | `新闻动态` tab + 左侧配图 + 右侧标题列表 + `more>>` | 389px |
| 风采展示 | **左侧竖排标题条** + 右侧 4 个方形图位 | 298px |
| 六宫格 | 通信工程（中外合作办学）/ 软件工程（中外合作办学）/ 来华留学 / 招生信息 / 就业信息 / 下载专区 | 386px |
| 双列列表 | 招生信息（4 条，日期右对齐）+ 就业信息（2 条） | — |
| 页脚 | 友情链接横排 6 个 + 地址/电话/传真/邮编 + 院徽 | 147px |
| 悬浮快捷导航 | 右侧竖排（`quick-nav`） | 465px |

**关键手法**：`风采展示` 用一条**竖排文字标签**（`writing-mode: vertical-rl`）代替横排标题，省下 60px 宽度给图位，同时形成"书脊"般的版面锚点。这是政务站里少见的巧思，成本 2 行 CSS。

## 3. 视觉系统：为什么它"看着旧"

| 症状 | 证据 |
|---|---|
| **没有字号阶梯** | 15px 用了 352 次，几乎一切正文都是 15px；标题与正文只靠字重区分 |
| **没有圆角体系** | 全站只有 4/5/6px 各 1–2 处 |
| **靠底图撑品牌** | 院名是 `college_title.png`（57 KB 的书法体图），不是文字排版 |
| **色彩只有两个色块** | `#1a3a6c` 深藏青 + `#8f000b` 暗红，其余全是灰阶 |
| **方正** | 六宫格按钮是 `#efefef` 纯灰底 + 1px 无、hover 变红；无阴影无圆角 |
| **三套 UI 库并存** | Bootstrap 3 + Element UI + layui 的样式同时在场，导致行高/边距互相打架 |

**可迁移的反面教训**：一个站点只要有 `bootstrap.css` 就够排版了，再叠 Element UI 与 layui 只会让"同一间距有 3 个真值"。我们已经用 Tailwind 一套工具链，**不要为了"某个组件好用"再引入第二套 UI 库**。

## 4. 无障碍与语义问题（逐条可核对）

1. **导航项用 `<h3>`**：`<h3>首页</h3>` `<h3>学院概况</h3>` … 8 个。屏幕阅读器的标题大纲会被导航项淹没，且导航本应是 `<nav><ul><li><a>`。
2. **无 `:focus-visible` 样式**：键盘 Tab 只能靠浏览器默认描边（与自定义样式冲突）。
3. **AOS 入场动画无降级**：`aos="fade-up"` 属性 + `aos.js`，CSS 里没有 `prefers-reduced-motion` 分支。
4. **图片 alt 多为空**：`<img src="images/logo_03.png" alt="">`、`alt=""` 的信息图。
5. **外包 JS 里的编码损坏**：页面内联脚本注释出现 `<!-- �� 智能导航跳转` —— 与联合学院那 10 处 U+FFFD 同源，属同一次编码转换留下的伤痕（见拆解 04 §5）。

## 6. 可借鉴（只有两条，但都是硬需求）

### 6.1 按"读者是谁"给入口 ★★★

它的六宫格本质是**四条读者路径**：考生（招生信息）、在校生（学生事务/就业）、教师（师资/教学）、国际生（Study@CQUPT）。

我们的五个栏目是按**内容类型**分的（案例 / 分析 / 拆解 / 故事 / 工具）。对一个作品集来说，读者其实只有三类：

| 读者 | 他要什么 | 我们现在的入口 |
|---|---|---|
| 面试官/HR | 3 分钟内判断"这人能不能用" | 无（要自己滚 4300px） |
| 同行/评审 | 看方法论是否站得住 | 有（拆解/分析栏目） |
| 老师/同学 | 看"最近在做什么" | 无 |

**建议**：首页 hero 下方加一行 3 个"路径入口"：`3 分钟速览 →`、`看方法论 →`、`看最近更新 →`。这是本站最值得抄的一条。

### 6.2 日期 + 标题 + more>> 的扫读列表 ★★

它的招生信息区：`标题（可点）` + 右侧 `2025年11月10日`，4 行一个区块，行高一致，日期右对齐。

我们已有 `pubDatetime` 与 `Datetime.astro`，但列表页的日期是"卡片内小字"。建议在案例列表页提供**紧凑视图**（标题 + 日期右对齐 + 一行摘要），供"扫读"用——现在只有卡片视图，5 篇就要滚 1200px。

## 7. 明确不借鉴

- 10px 根字号（`62.5%` 技巧）：rem 换算方便，但会把"根字号"这个无障碍用户的第一调节项钉死。
- 三套 UI 库并存。
- 用图片承担院名/标题（不可选中、不可被搜索引擎读取、不随字号缩放）。
- 无字号阶梯的平面排版。
