## 摘要

1. **栏高上限业界只有两种写法**：Docusaurus / Nextra 用 `position: sticky` + `max-height: calc(100vh - 偏移)` + `overflow-y: auto`；Starlight / VitePress 用 `position: fixed` + `height: 100vh` + `overflow-y: auto`。本项目无粘性页头（`src` 全量 grep `sticky` 只命中 `BackToTopButton.astro:13`），所以 Docusaurus 写法可直接抄，偏移取 `1rem`。【官方源码】packages/docusaurus-theme-classic/src/theme/TOC/styles.module.css
2. **「目录比视口高」不是靠截断，是靠容器自己滚**：5 个实现全部给滚动容器加 `overflow-y: auto`，没有一个只显示前 N 条。Starlight 与 VitePress 额外加 `scrollbar-width: none` 隐藏滚动条（避免滚动条本身占宽导致跳版）。【官方源码】Starlight dist/components/TwoColumnContent.astro；VitePress src/client/theme-default/components/VPDoc.vue
3. **祖先 `overflow` 破坏 sticky 的官方依据已找到**：sticky 的偏移相对「最近 scrollport」，而 MDN 明确 `hidden`/`scroll`/`auto` 都会让元素盒子成为 scroll container，只有 `visible` 与 `clip` 不会。所以**非根祖先**上的 `overflow: hidden` 会把 sticky 锁死在那 个盒子里；`overflow: clip` 是官方逃生门。【官方规范】【官方文档】
4. **本项目 `<html class="overflow-y-scroll">` 不构成这个坑**：`html` 是根元素，其 scrollport 就是视口那条，属于 sticky 的正常工作路径。真正的禁忌是给右栏的中间祖先加 `overflow-hidden`。【官方规范】+ 本项目源码 src/layouts/Layout.astro:68
5. **若用 `position: fixed`，真正的雷是祖先的 `transform` / `filter` / `contain: paint`**：MDN 列明这些值会把 fixed 的包含块从视口改成该祖先的 padding box。Starlight / VitePress 敢用 fixed 是因为它们的祖先链干净，不是因为这写法更安全。【官方文档】MDN Containing block
6. **active 高亮两大流派，阈值口径互不相同**：IntersectionObserver 派（Starlight，**不设 threshold**，只用 `rootMargin: '-{top}px 0% {top+53-clientHeight}px'`）；scroll + 矩形比较派（Docusaurus 用「视口上半 50vh 归当前标题，否则归上一个」；VitePress 用「最后一个满足 `top <= scrollY + scrollMarginTop + 4` 的标题」；tocbot 用「第一个满足 `offsetTop > scrollTop + headingsOffset + 10` 的标题的前一个」）。【官方源码】四处源码原文
7. **「点击目录跳转不闪」有现成答案，且只有两家做了**：VitePress 用 `ignoreScrollOnce` 布尔位跳过一次 scroll 回调；tocbot 用 `isClick` + `scrollSmoothDuration`（默认 420ms）定时复位。Docusaurus 与 Starlight **都没做**，Docusaurus 甚至把 `link.scrollIntoView({block:'nearest'})` 注释掉了。【官方源码】
8. **目录标题元素：5 家里 4 家不用真标题**。VitePress 用 `<div role="heading" aria-level="2">`、Nextra 用 `<p>`、MkDocs Material 用 `<label for>`、Docusaurus 根本不渲染标题；**只有 Starlight 用了真 `<h2 id="starlight__on-this-page">`**。要零标题成本就学前四家。【官方源码】
9. **active 的 a11y 惯例是 `aria-current="true"` 而非 `page`**：Starlight 的 CSS 选择器就是 `a[aria-current='true']`；其余三家（VitePress / Docusaurus / Nextra）都只用 class，不用 ARIA。`aria-current="page"` 是本项目 src/components/Breadcrumb.astro:76 已用于面包屑的取值，两者语义不同，别混用。【官方源码】+ 本项目源码
10. **本项目已有 `remark-toc` + `remark-collapse` 在跑**（src/../astro.config.ts:42-43），默认匹配 `'(table[ -]of[ -])?contents?|toc'`，一旦有正文写出 `## Contents` 就会生成**第二个正文内目录**（并被 collapse 包成 `<details>`），与右栏重复。当前全站 grep 无命中，是惰性状态。【官方源码】remark-toc@9 readme + 本项目源码

```js
class StarlightTOC extends HTMLElement {
	_current = this.querySelector("a[aria-current=\"true\"]");
	minH = parseInt(this.dataset.minH || "2", 10);
	maxH = parseInt(this.dataset.maxH || "3", 10);
	tocHeadingSelector = `h1#${PAGE_TITLE_ID},:where(${[...Array.from({ length: 1 + this.maxH - this.minH }).map((_, index) => `h${this.minH + index}`)].join()})[id]`;
	set current(link) {
		if (link === this._current) return;
		if (this._current) this._current.removeAttribute("aria-current");
		link.setAttribute("aria-current", "true");
		this._current = link;
	}
	onIdle = (cb) => (window.requestIdleCallback || ((cb) => setTimeout(cb, 1)))(cb);
```

```js
		const observe = () => {
			if (observer) return;
			observer = new IntersectionObserver(setCurrent, { rootMargin: this.getRootMargin() });
			toObserve.forEach((h) => observer.observe(h));
		};
		observe();
		let timeout;
		window.addEventListener("resize", () => {
			if (observer) {
				observer.disconnect();
				observer = void 0;
			}
			clearTimeout(timeout);
			timeout = setTimeout(() => this.onIdle(observe), 200);
		});
	}
	getRootMargin() {
		/** Start intersections at nav height + 2rem padding. */
		const top = (document.querySelector("header")?.getBoundingClientRect().height || 0) + (this.querySelector("summary")?.getBoundingClientRect().height || 0) + 32;
		return `-${top}px 0% ${top + 53 - document.documentElement.clientHeight}px`;
	}
```

要点（本任务最硬的一条）：
- `new IntersectionObserver(setCurrent, { rootMargin: ... })` —— **只传 `rootMargin`，完全没传 `threshold`**（默认 0）。
- `getRootMargin()` 返回三值字符串：上边 `-{top}px`、左右 `0%`、下边 `{top + 53 - clientHeight}px`。`top = 页头高 + summary 高 + 32`。那个 `53` 是源码裸魔数，无可读注释。
- observe 的目标不是「只看标题」，而是四组选择器，再用 `getElementHeading()` 从命中的块向上/向前回溯到最近的标题。原文：


- 初始化走 `requestIdleCallback`（无此 API 时退化 `setTimeout(cb, 1)`）——这是为 CLS/性能门禁服务的，不阻塞首屏。

**2.1 高亮算法：scroll + 绝对偏移，带点击防闪**（`src/client/theme-default/composables/outline.ts`）【官方源码】

```ts
export function useActiveAnchor(
  container: TemplateRef<HTMLElement>,
  marker: TemplateRef<HTMLElement>
): void {
  const isAsideVisible = useMediaQuery('(min-width: 80rem)')

  const onScroll = throttleAndDebounce(setActiveLink, 100)

  let prevActiveLink: HTMLAnchorElement | null = null
  let ignoreScrollOnce: boolean = false

  onMounted(() => {
    requestAnimationFrame(setActiveLink)
    window.addEventListener('scroll', onScroll)
    container.value?.addEventListener('click', onClick)
  })
```

```ts
  function onClick(e: MouseEvent) {
    if (!isAsideVisible.value) {
      return
    }

    const hash =
      e.target instanceof Element ? e.target.closest('a')?.hash : null

    if (hash) {
      ignoreScrollOnce = true
      activateLink(hash)
    }
  }

  function setActiveLink() {
    if (!isAsideVisible.value) {
      return
    }

    if (ignoreScrollOnce) {
      ignoreScrollOnce = false
      return
    }

    const scrollY = window.scrollY
    const innerHeight = window.innerHeight
    const offsetHeight = document.body.offsetHeight
    const isBottom = scrollY + innerHeight - offsetHeight >= 0

    // resolvedHeaders may be repositioned, hidden or fix positioned
    const headers = resolvedHeaders
      .map(({ element, link }) => ({
        link,
        top: getAbsoluteTop(element),
        scrollMarginTop:
          Number.parseFloat(getComputedStyle(element).scrollMarginTop) || 0
      }))
      .filter(({ top }) => !Number.isNaN(top))
      .sort((a, b) => a.top - b.top)

    // no headers available for active link
    if (!headers.length) {
      activateLink(null)
      return
    }

    // page top
    if (scrollY < 1) {
      activateLink(null)
      return
    }

    // page bottom - highlight last link
    if (isBottom) {
      activateLink(headers.at(-1)?.link ?? null)
      return
    }

    // find the last header above the top of viewport
    let activeLink: string | null = null
    for (const { link, top, scrollMarginTop } of headers) {
      if (top > scrollY + scrollMarginTop + 4) {
        break
      }
      activeLink = link
    }
    activateLink(activeLink)
  }
```

```ts
function getAbsoluteTop(element: HTMLElement): number {
  let offsetTop = 0
  while (element !== document.body) {
    if (element === null) {
      // child element is:
      // - not attached to the DOM (display: none)
      // - set to fixed position (not scrollable)
      // - body or html element (null offsetParent)
      return NaN
    }
    offsetTop += element.offsetTop
    element = element.offsetParent as HTMLElement
  }
  return offsetTop
}
```

active 真正落地的地方：

```ts
  function activateLink(hash: string | null) {
    const activeLink =
      hash != null
        ? (container.value?.querySelector<HTMLAnchorElement>(
            `a[href\$="${decodeURIComponent(hash)}"]`
          ) ?? null)
        : null

    if (activeLink === prevActiveLink) return

    prevActiveLink?.classList.remove('active')
    prevActiveLink = activeLink

    if (activeLink) {
      activeLink.classList.add('active')
      if (marker.value) {
        // the links' offsetParent (.root) sits below the outline title while
        // the marker is offset from .content, so re-align their origins
        marker.value.style.top =
          activeLink.offsetTop +
          ((activeLink.offsetParent as HTMLElement)?.offsetTop ?? 0) +
          (activeLink.offsetHeight - marker.value.offsetHeight) / 2 +
          'px'
        marker.value.style.opacity = '1'
      }
      activeLink.scrollIntoView({ block: 'nearest', behavior: 'smooth' })
    } else if (marker.value) {
      marker.value.style.top = ''
      marker.value.style.opacity = '0'
    }
  }
```

**要点（阈值口径）**：active = **最后一个满足 `top <= scrollY + scrollMarginTop + 4` 的标题**；`scrollY < 1` 时清空；滚到底时取最后一个。scroll 监听是 `throttleAndDebounce(setActiveLink, 100)`（100ms）。**点击防闪就是 `ignoreScrollOnce`**：点目录时置位、立即 `activateLink(hash)`，下一次 scroll 回调直接 return 并清位。active 后还会 `scrollIntoView({block:'nearest'})` 让目录项自己滚进视野。另有 `onUpdated(() => { activateLink(location.hash) })` 用于路由切换后按 hash 复位。

```ts
/**
 * If the anchor has no height and is just a "marker" in the DOM; we'll use the
 * parent (normally the link text) rect boundaries instead
 */
function getVisibleBoundingClientRect(element: HTMLElement): DOMRect {
  const rect = element.getBoundingClientRect();
  const hasNoHeight = rect.top === rect.bottom;
  if (hasNoHeight) {
    return getVisibleBoundingClientRect(element.parentNode as HTMLElement);
  }
  return rect;
}

/**
 * Considering we divide viewport into 2 zones of each 50vh, this returns true
 * if an element is in the first zone (i.e., appear in viewport, near the top)
 */
function isInViewportTopHalf(boundingRect: DOMRect) {
  return boundingRect.top > 0 && boundingRect.bottom < window.innerHeight / 2;
}
```

```ts
function getActiveAnchor(
  anchors: HTMLElement[],
  {
    anchorTopOffset,
  }: {
    anchorTopOffset: number;
  },
): Element | null {
  // Naming is hard: The "nextVisibleAnchor" is the first anchor that appear
  // under the viewport top boundary. It does not mean this anchor is visible
  // yet, but if user continues scrolling down, it will be the first to become
  // visible
  const nextVisibleAnchor = anchors.find((anchor) => {
    const boundingRect = getVisibleBoundingClientRect(anchor);
    return boundingRect.top >= anchorTopOffset;
  });

  if (nextVisibleAnchor) {
    const boundingRect = getVisibleBoundingClientRect(nextVisibleAnchor);
    // If anchor is in the top half of the viewport: it is the one we consider
    // "active" (unless it's too close to the top and and soon to be scrolled
    // outside viewport)
    if (isInViewportTopHalf(boundingRect)) {
      return nextVisibleAnchor;
    }
    // If anchor is in the bottom half of the viewport, or under the viewport,
    // we consider the active anchor is the previous one. This is because the
    // main text appearing in the user screen mostly belong to the previous
    // anchor. Returns null for the first anchor, see
    // https://github.com/facebook/docusaurus/issues/5318
    return anchors[anchors.indexOf(nextVisibleAnchor) - 1] ?? null;
  }
  // No anchor under viewport top (i.e. we are at the bottom of the page),
  // highlight the last anchor found
  return anchors[anchors.length - 1] ?? null;
}
```

```js
    options.tocElement ||
```

**6.6 规范与官方文档：sticky 的官方定义与 `overflow` 陷阱**

CSS Positioned Layout Module Level 3，`#sticky-pos`（`drafts.csswg.org/css-position-3/`）【官方规范】原文：

> Sticky positioning is similar to relative positioning except the offsets are automatically calculated in reference to the nearest scrollport. For a sticky positioned box, the inset properties represent insets from the respective edges of the scrollport of the nearest scroll container with a matching scrollable axis, defining the sticky view rectangle used to constrain the box's position. […] If both inset properties in a given axis are auto, no offsets are added in that axis; the element stays where it was laid out in that axis.

MDN `overflow`（`developer.mozilla.org/en-US/docs/Web/CSS/overflow`）【官方文档】对每个取值是否构成 scroll container 的原文：

> **visible** — Overflow content is not clipped and may be visible outside the element's padding box. **The element box is not a scroll container.** This is the default value.
> **hidden** — Overflow content is clipped at the element's padding box, hiding the clipped content. When overflowing, **the element box is a scroll container with no scroll bars**; scrolling is still possible via other methods including tabbing to hidden focusable elements, properties such as scrollLeft property, and methods like scrollTo().
> **clip** — Overflow content is clipped at the element's overflow clip edge defined by the overflow-clip-margin property. **The element box is not a scroll container**, clipped content is not visible, and programmatic scrolling is not supported.
> **scroll** — Overflow content is clipped at the element's padding box. Whether overflowing or not, **the element box is always a scroll container** displaying scroll bars.
> **auto** — Overflow content is clipped at the element's padding box. When overflowing, **the element box is a scroll container** displaying scroll bars.

**由这两条推出的结论（本任务问题一的官方答案）**：
- sticky 的约束矩形来自「最近的 scrollport」。**非根祖先**一旦有 `overflow: hidden | scroll | auto`，它自己就成了最近的 scroll container，sticky 元素就被锁在那个盒子的滚动范围内——而不是视口。这就是流传的「祖先 overflow 破坏 sticky」的规范级原因。
- **`overflow: clip` 不构成 scroll container**，所以把祖先的 `overflow: hidden` 换成 `overflow: clip` 是官方逃生门（代价：`clip` 不支持程序化滚动，但滚动容器本来也不需要）。
- **`overflow-x: clip` 配 `overflow-y: visible`** 不会把 `visible` 强制算成 `auto`（`clip` 是 `visible` 唯一的合法对偶），所以「只裁横向溢出」的写法是 sticky 安全的。

MDN `position` 关于阈值必填的原文【官方文档】：

> You must specify a threshold with at least one of top, right, bottom, or left for sticky positioning to behave as expected. Otherwise, it will be indistinguishable from relative positioning.

（即：写 `position: sticky` 而不写 `top`/`bottom` 等于没写。）

**6.7 `position: fixed` 派的真正雷区：祖先会抢走包含块**

MDN "Containing block"（`developer.mozilla.org/en-US/docs/Web/CSS/CSS_display/Containing_block`）【官方文档】原文：

> If the position property is fixed, the containing block is established by the viewport (in the case of continuous media) or the page area (in the case of paged media).
> If the position property is absolute or fixed, the containing block may also be formed by the edge of the padding box of the nearest ancestor element that has any of the following:
> - A filter, backdrop-filter, transform, perspective, rotate, scale, or translate value other than none.
> - A contain value of layout, paint, strict or content (e.g., contain: paint;).
> - A will-change value containing a property for which a non-initial value would form a containing block (e.g. filter or transform).
> - A content-visibility value of auto.

要点：Starlight 与 VitePress 都选了 `position: fixed`，但**它们没有任何祖先带 transform/filter/contain**。一旦右栏的某个中间祖先加了其中之一，fixed 栏会突然相对那个祖先定位（视觉上表现为「跑到页面中间 / 被裁掉」）。这是 fixed 派必须自己保证的前提，sticky 派没有这个问题。

**6.8 `IntersectionObserver.rootMargin` 的官方语义**

MDN `IntersectionObserver.rootMargin`（`developer.mozilla.org/en-US/docs/Web/API/IntersectionObserver/rootMargin`）【官方文档】原文：

> The rootMargin read-only property of the IntersectionObserver interface is a string with syntax similar to that of the CSS margin property. Each side of the rectangle represented by rootMargin is added to the corresponding side in the root element's bounding box before the intersection test is performed.

要点：`rootMargin` 是**在求交之前把 root 的矩形按四边外扩/内缩**。Starlight 用 `'-{top}px 0% {top+53-clientHeight}px'` 就是把 root 收缩成视口顶部之下、视口底部之上的一条**窄带**；窄带内一旦有目标块命中（`isIntersecting`），就把它回溯成标题并置为 active。这就是它不需要 `threshold` 的原因——**它靠 rootMargin 把 root 变成一条线，而不是靠 threshold 比例**。

5. **不要用 `IntersectionObserver`（Starlight 派）。** 不是因为不好，而是因为它的参数**不可移植**：`rootMargin` 里那个 `53` 是源码裸魔数、`32` 是「2rem padding」的硬编码、还要加上 `header` 与 `summary` 的实时高度（§1.3【官方源码】）。本项目没有粘性页头，这套换算的输入少了一大半，收益不足以抵消调试成本。等本项目 h2 数量涨到需要「观察正文块而不只是标题」时再考虑。

6. **不要忽略 `remark-toc` 这颗地雷。** `C:\dev\pm-forge\site\astro.config.ts:42-43` 已经装了 `remarkToc` 与 `[remarkCollapse, { test: "Table of contents" }]`。【本项目实测】当前全站无正文命中，是惰性状态。但只要有人写出 `## Contents` / `## TOC`（remark-toc@9 默认正则是 `'(table[ -]of[ -])?contents?|toc'`【官方源码】），页面就会**凭空多出一个正文内目录**，而且被 `remarkCollapse` 包成 `<details>`——与右栏功能重复、风格冲突。要么给 `remarkToc` 显式关掉，要么在写作规范里注明「正文禁止出现 Contents/TOC 标题」。（顺带一提：中文 `## 目录` **不会**命中这个正则，别误以为它安全就以为它一致。）

7. **不要为此改动 `:target { scroll-margin-block: 1rem }`。** `C:\dev\pm-forge\site\src\styles\global.css:65-67` 已经处理了锚点落点。【本项目实测】VitePress 需要 `scroll-margin-top: calc(页头 + 2rem)` 是因为它有固定页头（`.outline-link` 的 CSS 原文，§2.2）；本项目页头不固定、右栏在侧边，没有新的遮挡物，**这条 CSS 一行都不用动**。这也满足「移动端一行 CSS 都不变」。

### ⚠️ 需要本项目自己实测的两点（我不能替它下结论）

- **`<html class="overflow-y-scroll">`（`C:\dev\pm-forge\site\src\layouts\Layout.astro:68`）对 sticky 的影响。** 按 §6.6 两条官方依据推理：`overflow-y: scroll` 让 `html` 成为 scroll container，而 `html` 是根元素、其 scrollport 就是视口那条，所以 sticky 应当照常工作（这也是 `overflow-y: scroll` 防滚动条抖动的常见用法）。但**我没有找到任何官方文档直接断言这个特例**，也**没有在本项目里跑过浏览器验证**。因此标记为【未核实】：请在实际加栏后，在 1280/1440/1600/1920 四个视口各确认一次右栏是否跟随滚动。若发现异常，第一嫌疑就是它。
- **MkDocs Material 的目录在移动端的具体形态。** 我只抓到了服务端 Jinja 模板（`partials/toc.html`、`partials/toc-item.html`）与滚动高亮 TS（`components/toc/index.ts`），**没有抓到移动端抽屉/侧滑的样式来源**。所以「Material 移动端怎么折叠目录」标记为【未核实】。已确认的移动端做法只有三家：Starlight（固定条 + `<details>` 下拉，三条关闭路径）、Docusaurus（`@media (width <= 996px) { display: none }` + 独立的 `TOCCollapsible` 折叠面板）、VitePress（`.aside { display: none }` → `min-width: 80rem` 才 `display: block`）。
