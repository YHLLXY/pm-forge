# 拆解 02 · CQUPTHUB 工作室官网（重点对象）

- 日期：2026-10-27
- 对象：<https://webapp.codeghub.com/release/app/admin/home/index.html>
- 方法：CDP 直连无头 Edge（1440×900 / 390×844），逐屏翻页截图 **17 张**（含 8 屏 × 多状态），采集 computed style，静态分析 59 KB 的 CSS 包与 138 KB 的 JS 包
- 证据：`docs/research/evidence/2026-10-27-外部站点拆解/`（`probe-codeghub.json`、`shoot.mjs`、`navwalk.mjs`、`final.mjs`）
- 结论先行见 §0；逐屏笔记见 §4；可借鉴清单见 §8

## 0. 结论先行

**它是"用一个统一的插画世界，把六件事讲成六页"的完整案例。技术上不复杂（Vue 3 + Tailwind v4 + 四组 keyframes），难的是美术与内容的组织。**

最值得我们学的不是"贴纸风"，而是这五件可迁移的事：

| # | 可迁移的点 | 我们的现状 | 价值 |
|---|---|---|---|
| 1 | **中英双语标题体系**（关于我们 / ABOUT US） | 只有中文栏目名 | ★★★ 成本极低，直接提升"机构感" |
| 2 | **每屏一个"徽章"锚点**（圆形 mint 色块 + 中文 + 英文） | 无 | ★★★ 让长页面有"章节感" |
| 3 | **数字指标前置**（20+ / 100+ / 4+ / 10+，56px 大字一屏看完） | 我们的数字只有 18px，埋在"本作品集包含"的 6 行明细里 | ★★★ 一眼看到体量 |
| 4 | **项目墙用缩略图**（26 个项目截图 + 底部渐变名字条） | **首页零截图** | ★★★ 最大短板，见 §8.4 |
| 5 | **主从结构**（左侧名单 + 右侧详情卡） | 尚无主从结构 | ★★ 可用于"精选案例"或"证据面板" |

**不能照搬的**：整套手绘插画（约 10 张 webp、首屏约 920 KB）、单屏翻页（对 40+ 条目的作品集是灾难）、无限横向 marquee（无 reduced-motion 会让无障碍降级）。

## 2. 体验结构：它不是"长滚动"，是"翻页"

这是本次拆解最重要的一条结构性发现。

| 观察 | 证据 |
|---|---|
| 桌面文档高度恒为 900，无滚动条 | `document.scrollHeight = 900`，`#app` 高 900 |
| 滚轮一次 = 换一屏 | 用合成 `WheelEvent` 每 3 次一组，每次前进正好一屏 |
| 全站共享同一张插画底 | 首页、关于我们、联系我们截图的背景（HELLO 字样、粉星、网格纸、放射状薄荷光）完全一致 |
| 底部"白色纸边 + 双 chevron"常驻 | 每屏底部都是同一条白色弧形纸边与 `⌄⌄` |
| 前景内容随屏替换 | 节点数在 31 / 45 / 50 / 551 之间跳变，说明组件按屏挂载 |

**结论**：整站 = **一张固定插画画布（背景层）+ 一个按屏替换的前景层 + 常驻的纸边与导航**。
这种做法的直接好处是"换屏不跳、视觉连贯"；代价是**信息不可被检索**（百度/搜狗爬不到内容，因为转场组件在 JS 里）、**深度阅读不友好**、**单屏 900px 装不下长文**。

它自己也承认这个代价：**移动端完全放弃了翻页，改成 9,587px 的普通长滚动**（`min-h-[100svh]` + `px-5 py-14` 的章节堆叠）。同一套内容，两套交互——这是"桌面要仪式感、移动要效率"的典型取舍。

## 3. 美术语言拆解

### 3.1 调色板：一个墨绿 + 一个奶油 + 一个贴纸黄

从 59 KB 的 CSS 包里统计出现次数：

| 色值 | 次数 | 角色 |
|---|---|---|
| `#033b37` | 27 | **墨绿**：正文字、标题字、描边 |
| `#0a665f` | 24 | **主青**：卡片底、按钮、图标 |
| `#f7d460` | 9 | **贴纸黄**：高亮块、圆点、强调 |
| `#ebf5f0` / `#eaf5f0` / `#f4f9f7` / `#e4f3ec` | 7/2/2/2 | 薄荷底（卡片与页面底） |
| `#917109` | 7 | 深金（黄底上的文字） |
| `#fff8e0` | 5 | 奶油（时间轴卡、便签纸） |
| `#2f9e77` / `#2f8a84` / `#17514b` | 2/4/3 | 青的阶梯：hover / 次级 / 深 |

**规律**：只有 **1 个深色 + 1 个亮色 + 1 组同色阶梯**，其余全是"纸"的颜色。它没有红/蓝/紫，"彩色"全部靠插画本身（粉星、橙红药丸、蓝 HELLO）。

对照我们：我们的调色板是**暖纸底 + 一个蓝 + 5 个栏目色**（`#0b5fa5` / `#0f6b73` / `#4f46b8` / `#a24d05` / `#2a6b45`）。栏目色是我们"分类即视觉"的核心资产，不该砍；但它缺一个**统一的强调色**来做"贴纸黄"的活——目前我们用 `--accent: #0b6bcb`（蓝），与五个栏目色同属"冷/深"家族，缺少一个"亮"的点缀色。

### 3.2 字体：零 webfont，靠字重与字距

| 层级 | 做法 |
|---|---|
| 一级（页面标题） | 中文 32–36px / 700 / `#033b37` |
| 二级（英文标签） | 全大写 / 18–20px / `letter-spacing` 拉开 / 同色 |
| 三级（卡片标题） | 18–20px / 700 |
| 正文 | 15–16px / 400 / 行高约 1.9 |
| 辅助 | 13–14px / 400 |

**关键手法**：**中文粗体 + 英文全大写细体** 并置。中文给"分量"，英文给"格调与呼吸"。英文全大写天然有"标签感"，且不抢中文。

实测移动端字号分布里出现 `16px × 161`、`11px × 121` 这种量级，说明正文 16、注脚 11–12，与桌面一致。

### 3.3 图形语法：手账 / 贴纸 / 剪纸

| 构件 | 做法 | 作用 |
|---|---|---|
| **双线框** | 卡片本体 1px 墨绿描边 + 外层偏移 4–6px 的第二道描边 | "贴纸剪下来贴在纸上"的厚度感 |
| **描边胶囊标题** | 标题外包一层 1px 圆角胶囊 + 虚线内边 | 让纯文字变成"标签" |
| **网点/半调** | 粉色星星fill 是 dot pattern | 印刷品质感 |
| **胶带/药丸** | 旋转 3–8° 的圆角长条（粉、黄） | 打破网格的手工痕迹 |
| **巨型水印字** | `CQUPT HUB` 半透明压在卡片后；项目页是一条 -60° 斜贯全屏的墨绿字带 | 品牌记忆 + 分割版面 |
| **L 形角标** | 四角的直角括号（取景框） | 暗示"这是一个可选择/可滚动的区域" |
| **四角星 sparkle** | 大小两枚，散落 | 氛围，成本极低 |
| **纸边** | 底部白色大弧线，压住插画 | 统一收口，每屏必现 |

### 3.4 版式：单屏、中央构图、大量留白

- 1440×900 一屏只讲一件事；标题常在左上（`px-5 py-14` 的章节版式）或正中（`关于我们`）。
- 卡片从不铺满，永远留 20%–30% 的空，让插画透气。
- 装饰元素（星星、药丸、胶带）**只出现在空白处**，从不压字。

## 5. 交互与动效

### 5.1 三组 keyframes 撑起全站

| 名称 | 定义 | 用途 |
|---|---|---|
| `marqueeLeft` | `0%: translate(0) → 100%: translate(-50%)` | 项目墙左行；内容复制两份，位移 50% 即无缝 |
| `marqueeRight` | 反向（`-50% → 0`） | 项目墙右行 |
| `jellyPop` | 6 段 squash & stretch：`scale(.4,.45) rotate(-6deg)` → `scale(.92,1.18)` → `scale(1.1,.86)` → … → `scale(1)` | 贴纸/徽章"啪"地贴上去的弹跳 |
| `copyPopIn` | `opacity 0→1` + `translateY(-10px)→0`，0.2s | 复制成功的浮层提示 |

**`jellyPop` 值得单独记一笔**：它不是简单的 `scale` 弹出，而是**先压扁、再过冲、再回弹**的 6 帧序列，还带 `rotate(-6deg)→0` 的旋转收敛。这正是"手绘动画感"的来源——成本只有 1 个 `@keyframes`。

### 5.2 交互清单

| 交互 | 实现 |
|---|---|
| 翻页 | `wheel` 事件驱动，一次手势一屏；`overflow` 锁死在 900px |
| 导航 hover | `transition-colors duration-200` + 变 `#2f9e77` |
| 页面切换 | Vue `<Transition>`（`.qr-fade-enter-active` 0.2s opacity） |
| 成员列表切换 | 点击名单项 → 右侧详情卡换内容（主从联动） |
| 移动端 | 无翻页，普通滚动 |

### 5.3 无障碍缺口（可核对的硬事实）

- CSS 里 `prefers-reduced-motion` **0 处** → 无限 marquee 与 jellyPop 对前庭敏感用户不友好
- `:focus-visible` 只有 **2 处** → 键盘用户在 5 个导航项之外几乎没有可见焦点
- 全站无暗色模式

**对我们的意义**：我们站点的 Lighthouse 六页 a11y 全绿是硬门槛（`docs/STATUS.md` M3 记录，a11y 从 87 修到 100）。学习它时**必须把它这三条当反面教材**，而不是连动效一起搬。

## 6. 内容策略（比美术更值得学）

它在"一个学生工作室凭什么值得信"这件事上，用了四层证据：

| 层 | 手法 | 原文示例 |
|---|---|---|
| ① 量 | 四个数字撑体量 | `20+ 项目经验` `100+ 项目参加成员` `4+ 核心业务方向` `10+ 合作项目` |
| ② 名 | 26 个项目逐条列名，且**每条都有截图** | 仓储物流实训交互、超级采煤侠·电流大冒险、法典、规程小卫士…… |
| ③ 路 | 把"成长"画成 1→4 的路径，再说清"能获得什么" | 学习成长 → 项目实践 → 能力提升 → 核心培养；「真实产品开发经历」「简历资产」 |
| ④ 果 | 成员去向逐人列出（姓名脱敏 `陈*`）、公司、岗位、base 地 | 林子 26 届 · 工作室负责人&产品组长 · 腾讯 · 产品经理 · 深圳 |

**这四层正好是我们缺的"可视化"**：

- 我们有量（5 案例 / 40 条实测 / 6 份报告），但**只出现在一张表格里**；
- 我们有"名"（案例标题），但**没有一个可看的封面**；
- 我们有"路"（四段式方法论），但**是文字不是路径图**；
- 我们**没有"果"**（当然，学生本人还没有去向，这一层不该硬造）。

## 7. 工程侧

| 项 | 观察 | 对我们的启示 |
|---|---|---|
| 框架 | Vue 3 SFC（scoped `data-v-*`）+ Tailwind v4 + Vite 构建 | 我们的 Astro 是"零 JS 默认"，路线相反但不冲突 |

## 8. 可借鉴清单（落到我们的具体改法）

### 8.1 中英双语标题体系 ★★★

- 现状：`精选案例` / `数据分析` / `AI 产品拆解` / `数据故事` / `AI PM 工具箱`，纯中文。
- 建议：每个板块标题下加一行英文全大写小字，`letter-spacing: .12em`，颜色用 `--muted-foreground`：
  ```
  精选案例
  SELECTED CASES
  ```
- 成本：一个 `h2` 下加一个 `<p class="eyebrow">`，样式 6 行。**投入产出比最高的一条。**

### 8.2 板块"徽章"锚点 ★★★

它的"圆形薄荷徽章 + 中文 + 英文两行"（`项目展示 / SHOWREEL`）是**章节锚点**：无论滚到哪一屏，右下角总有一个"你在这里"的标记。

我们的对应做法（不用圆形贴纸，用**档案式标签**更贴我们的语言）：

- 每个板块左上角放一枚 `§ 02 / 精选案例` 的小方标（等宽字体、1px 描边、无圆角）；
- 滚动时 sticky 在版心底边，显示"当前板块 / 总板块数"。

### 8.3 数字前置 ★★★

- 现状：`本作品集包含` 表格（5 篇案例 / 2 篇数据 / 4 组拆解 / 40 条实测 / 6 份报告）+ 一行"更新于 2026年10月7日"。
- 建议改成 4 个大数字（56px，`--accent` 或一个新增的"朱红"强调色）+ 12px 小标签：
  ```
  5        40        4        6
  案例研究   条实测任务   组对照拆解   份工具报告
  ```
- 依据：法典用 3 张卡、CQUPTHUB 用 4 个数字，都在首屏 300px 内完成"体量证明"。

### 8.4 项目墙（最大短板）★★★

- 现状：首页 `#featured` 的三张卡是**纯文字封面**（`v1.0 → v1.30.3`、`6+ 轮`、`3 天`），读者看不到任何产品画面。
- 可借鉴的三件具体做法：
  1. **卡片底部渐变名字条**：`linear-gradient(transparent, rgba(0,0,0,.55))` + 白色粗体 + `>`；
  2. **卡面 = 真实截图**（我们已有 `dist/assets/dissections/*.png` 这类证据图，但只用在详情页）；
  3. **轻微上浮 + 阴影**（`translateY(-4px)` + `0 10px 30px -14px`）。
- 注意：**不做无限 marquee**（无障碍 + 阅读效率），改成 3×2 静态网格 + 悬停微动。

### 8.5 主从结构 ★★

- 它的"左圆盘名单 + 右异形详情卡"本质是 master-detail。
- 我们可以用在**精选案例**：左侧 5 个案例名（当前项加粗 + `▶`），右侧显示该案例的"封面 + 三个指标 + 一句结论"。桌面才有，移动端退化为纵向卡片。

### 8.6 时间轴 ★★

- 它的成长路径（横轴 + 交替卡片 + 虚线连接 + 交替色圆点）可以直接迁移到我们的**案例四段式**：把"背景与问题 / 我的角色 / 过程与关键取舍 / 结果与量化"画成 4 节点时间轴，正文仍是文字。
- 收益：读者一眼知道"这篇有 4 段、我在第 2 段"。

### 8.7 手工感小构件（换成我们的语汇）★★

| 它的 | 我们的替代 |
|---|---|
| 四角星 sparkle | 印刷体 `※` 或 `◆` 小标记 |
| 胶带 / 药丸 | 胶带贴纸 → "档案标签"（虚线边框矩形 + 微旋转 -1°） |
| L 形取景角 | 保留（中性、不挑风格） |
| 巨字水印 | 保留（我们的 `余翰林` 或 `CASE 01` 可以半透明压在卡后） |
| 纸边弧线 | 保留（作为全站页脚统一收口） |

### 8.8 统一 hover 过渡 ★★

它把 hover 收敛到 `200ms` + 单色 `#2f9e77`。我们现在是 11 处过渡、时长不一。建议收敛为两档：`120ms`（小构件：颜色、下划线）与 `200ms`（卡片：位移、阴影）。

## 9. 明确不借鉴

| 不借鉴 | 原因 |
|---|---|
| 整套手绘插画 + 吉祥物 | 需要一名插画师 + 约 10 张 webp（首屏 921 KB）；我们是文字驱动的作品集，插画会变成"装饰性噪音" |
| 桌面单屏翻页 | 40+ 条目无法翻页承载；且转场组件让内容不可被搜索引擎抓取、不可被 `Ctrl+F` 找到 |
| 无限横向 marquee | 无障碍（`prefers-reduced-motion` 0 处）+ 阅读效率；我们要的是"可核对"，不是"看起来很忙" |
| `100vh` 锁死单屏 | 1440×900 下装不下；1366×768 的笔记本上会直接溢出 |
| 零 webfont 的做法 | 与我们一致，不算"借鉴"，是共识 |
| 无暗色模式 | 我们已有 `prefers-color-scheme` 支持，不回退 |
