## A. 参考站点（12 个，均已实测打开）

### A1. Maggie Appleton —— https://maggieappleton.com/ 【实测】
- **定位**：数字花园 + 视觉散文（meta description 原文：digital garden of visual essays, notes, and patterns about programming, design, anthropology）。
- **它具体做对了什么（从 HTML 实测）**：
  - head 里内联了 `@view-transition { navigation: auto; }`，并且源码注释写明原因：「Inline so Chrome sees the opt-in before external CSS loads; otherwise it skips the transition on heavier pages.」→ 这是**纯 CSS 的跨文档视图过渡**，零 JS 框架。
  - 用 `<script type="speculationrules">` 做 hover 预取，`eagerness: "moderate"`；注释写明：「Astro's prefetch script stops Chrome from running cross-document view transitions, so it stays off.」→ **对 Astro 项目是一条关键坑位提醒**。
  - 用 `CSSViewTransitionRule in window` 特性检测给 html 加 `.no-vt` 类做优雅降级。
  - OG 图是按标题参数化的：`/og.png?title=Maggie+Appleton&description=...` → 构建期/边缘生成的封面，而不是手工画图。
  - 字体走 CSS 变量 `--font-sans / --font-body / --font-serif`，**无 Google Fonts**；产物路径 `/_astro/*.css`（Astro 构建）。
  - 首页 12 个 `<img>` + 64 个 inline `<svg>`，只有 3 个 `@keyframes`。
- **可直接搬进本项目**：cross-document View Transitions + speculationrules + 特性检测降级；按标题参数化生成 OG 封面；serif/sans 双字体变量。
- **不适合搬**：她的缩略图大量是手绘插画，这是团队产能出来的资产，本项目没有插画资源，硬学会变成"没有图的空框"。

## C. 可落地的具体技术手段

> 说明：本节只写我**实际抓取核验过**的做法与工具。未取得一手来源的子问题（背景质感、hero、页面级套路、暗色高级感）我会在末尾"未能验证"里如实列出，不编造。

### C1. 卡片视觉化：无图片内容站怎么做封面
- **构建期 HTML/CSS → SVG → PNG（可核验工具）**：satori —— https://github.com/vercel/satori 【实测 README】
  - README 原文定位："Satori: Enlightened library to convert HTML and CSS to SVG."
  - 用法要点（README 实测）：接受 JSX，`satori(element, { width, height, fonts: [{ name, data, weight, style }] })` 返回 SVG 字符串；**必须显式提供字体数据**（Buffer/ArrayBuffer）；转 PNG 用 Sharp（README 原文指向 `sharp` 的 librsvg 渲染）。
  - README 顶部同时指向 Vercel 官方 OG 文档与 Next.js 示例。
  - **对本项目的意义**：整条链路在**构建期**跑（`astro build` 时），产物是静态 PNG → 运行时零请求、零第三方 CDN，符合你的硬约束。
  - **风险**：Sharp / resvg 这类原生模块在国内 CI 下载可能慢或失败（参见 C5 里 cn-font-split README 明确给出国内镜像环境变量的做法）。【判断】建议先在 CI 上做一次可行性验证。
- **Astro 生态现成包**：https://www.npmjs.com/package/astro-og-images 【搜索】描述为 "Generate static Open Graph images during Astro builds from code-owned templates"（**未实测打开**）。
- **失效包警告**：https://github.com/Charca/astro-og-canvas 【失败：HTTP 404，仓库已不存在或已迁移】→ 不要照抄这个包名。
- **纯 SVG / 数据驱动封面（零新增依赖，最贴合你现状）**：既然项目里已经有 Observable Plot 与 DuckDB 的图表，可以用同一份数据在构建期渲染一张小折线/柱状图当封面。社区有 JSDOM 服务端渲染 Observable Plot 的做法：https://github.com/hrbrmstr/ojs-plot-jsdom 【搜索】标题为 "Using JSDOM to render Observable Plots on the command line"（**未实测打开**）。Observable 官方嵌入文档：https://observablehq.com/documentation/data-apps/embeds 【搜索，官网首页 https://observablehq.com/ 实测返回 429 Vercel Security Checkpoint，未能打开】。
- **【判断】** 三条路线按风险从低到高：纯 CSS/SVG 几何封面（零依赖） < 构建期 Plot→SVG（复用已有数据） < satori/Sharp 生成 PNG（最好看但引入原生依赖）。

### C4. 图表作为视觉元素

## D. 反例清单：2026 年的"AI 味 / 廉价感"

### D1. 学术一手来源（最硬的一条）
- **《Interrogating Design Homogenization in Web Vibe Coding》** —— https://arxiv.org/abs/2603.13036 【实测】
  - 提交日期：2026-03-13（arXiv:2603.13036, cs.HC）。作者：Donghoon Shin, Alice Gao, Rock Yuren Pang, Jaewook Lee, Katharina Reinecke, Emily Tseng。
  - 摘要要点（原文）：生成式 AI "is known for its tendency to homogenize, often reproducing dominant style conventions found in training data"；研究"vibe coding"（用户用提示词而非写代码来生成网站）是否导致设计同质化；发现"the push for frictionless generation can exacerbate homogenization and its harms"；提出以 "productive friction" 为中心的缓解框架，让创作者挑战默认输出、保留多样性。
  - **对求职作品集的直接含义**：LLM 默认产物 = 训练数据的主流风格 = 与大量其他作品集撞脸；"越顺滑越同质"。

### D2. 业界权威（YC Design Review，逐字稿实测）
来源：https://www.ycombinator.com/library/NL-common-mistakes-with-vibe-coded-websites 【实测】（YC 官方 Library；Aaron Epstein 主持，嘉宾 Raphael Schaad，Cron 创始人/设计师）。以下均为我在该页 `data-page` JSON 的 transcript 字段中读到的原话片段：
- **"AI 味"的具体长相**："You know what they look like - the purple gradients, annoying hover effects, sections that fade as you scroll."
- **紫蓝渐变被点名的原因不是颜色本身**："A couple other trends that we then identified was kind of like purple gradients. Um all of a sudden all startup websites um had purple gradients everywhere"；主持人补充："it’s not purple gradients are bad, nobody should ever use them. It’s that now they’re just so ubiquitous everywhere"（**关键是"到处都是"，不是"紫色有罪"**）。
- **滚动淡入淡出**：被列为"AI 味"典型特征之一（同上）。
- **emoji 当图标**："whenever I see the use of emojis, even though they’re not the system emojis, I feel like it’s a little lazy."（以及 "They use like these standard icons everywhere"）。
- **配色不协调**："I don’t think anyone would think of combining a red logo with purple as an accent color necessarily. Um uh it’s not necessarily complimentary."
- **hero 图文不一致**：poster image 与视频内容不同、"just very blurry here"，被点评为 confusing。
- **反例的另一面（重要）**：卡片 hover 动画被评为 "pretty tasteful"；说明**克制的微交互是被业界认可的**，被反对的是无意义动效。

### D3. 行业/媒体观察（实测正文）
- **Vandelay Design《Why Most AI-Generated Designs Look the Same (And How to Break the Pattern)》** —— https://www.vandelaydesign.com/why-ai-generated-designs-look-the-same/ 【实测】2025-11-04。原文："If you’ve seen one AI-generated website mockup, you’ve seen a hundred. - **Shuffle《Why Do Most AI-Generated Websites Look the Same?》** —— https://shuffle.dev/blog/2026/01/why-do-most-ai-generated-websites-look-the-same/ 【实测】2026-01-29。
- **NN/g Glassmorphism（原文抓取失败，但通过中文编译版核验了内容）**：
  - 原文 URL：https://www.nngroup.com/articles/glassmorphism/ （Megan Brown《Glassmorphism: Definition and Best Practices》）【失败：fetch failed】。
  - 中文编译版（优设）：https://www.uisdc.com/glassy-design-style 【实测】原文明确标注"原文引自 Megan Brown 的文章《Glassmorphism: Definition and Best Practices》"。可核验结论：玻璃态三特征 = 不透明度、背景模糊、描边与渐变；且"如果没有熟练掌握视觉设计原则，或者过度使用该形态，可能会影响界面可视性与可用性"。

## 附：本次调研可直接采用的 5 条"零争议事实"

1. Astro 官方文档站自报 Astro v7.2.10，Astro 官网自报 v7.3.5，Tailwind 文档站为 v4.3 → 你的技术栈是当前主流，官方文档可直接对照。（https://docs.astro.build/en/guides/fonts/ 、https://astro.build/showcase/ 、https://tailwindcss.com/docs/theme ）
2. Astro 自带 prefetch 会阻止 Chrome 的 cross-document View Transitions（Maggie Appleton 源码注释，实测）。
3. spring 缓动可以预编译成 CSS `linear()`，零 JS（Josh Comeau 实测 token）。
4. cn-font-split 提供 `CN_FONT_SPLIT_GH_HOST` 环境变量解决国内下载（README 实测）。
5. YC 与多篇 2026 年文章一致把"紫色渐变 + 到处滚动淡入 + emoji 图标 + 三等分特性卡片"点名为 AI 味特征（YC 逐字稿、Vandelay、Shuffle 实测）。
