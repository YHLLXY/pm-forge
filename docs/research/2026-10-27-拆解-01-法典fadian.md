# 拆解 01 · 法典 fadian.icu（法律 AI 助手落地页）

- 日期：2026-10-27
- 对象：<https://fadian.icu/>（CQUPTHUB 工作室项目，与其官网项目墙中的「法典项目」对应）
- 方法：CDP 直连无头 Edge，1440×900 与 390×844 双视口；采集 DOM、computed style、资源清单、双端截图；静态保存 HTML 与 CSS 包
- 证据：`docs/research/evidence/2026-10-27-外部站点拆解/`（脚本 + probe JSON）
- 结论先行见 §0

---

## 0. 结论先行

**这是一个「一屏讲完一个工具」的教科书式样板，值得我们抄的不是它的玻璃质感，而是三件事：版面被压缩到一屏内、字号只有 5 级、颜色只有一个蓝。**

| 它做对了什么 | 对我们的可用性 |
|---|---|
| 首屏 = 一句话 + 三张功能卡 + 一个主视觉，页面总高 969px | ★★★ 首页信息过载的解药，见 §6.1 |
| 字号阶梯只有 5 级（50 / 24 / 20 / 16 / 13），仅 14px 有 4 处零散用法 | ★★★ 与我们现有 11 档字号对比强烈（见 §6.2） |
| 语义色板 32 个 CSS 变量（shadcn 体系），主色唯一 | ★★★ 我们 21 个变量、**组件层 0 处裸 hex**；可把它固化成门禁（§6.3） |
| 单色标题 + 单色强调（`#18233f` 深蓝墨 + `#0067ae` 主蓝） | ★★★ 我们的栏目色有 5 套，视觉上更"花" |
| 所有图片走 `/_next/image` 按宽度出 srcset | ★★ 我们的证据图是原尺寸 PNG 直出 |
| 渐变短线（36×3px，右端渐隐）做标题与内容的分隔 | ★★ 低成本高质感的细节 |

**不适用**：玻璃质感 3D 主视觉（美术产能 + 与"可验证的产品决策"定位冲突）、单屏结构（作品集必须展示多案例）。

## 2. 信息架构与版面

单页、三段：

```
header 60px   左：logo 方块 + 法典 + 「AI」徽标（34×28，2px 主色描边）
main         左栏（lg 下占 65% 宽，max 920 / min 700，左内距 118px）
             ├ h1  50px / 1.16 / extrabold / #18233f，后半句换色 #0067ae
             ├ p   20px / #7b879e
             ├ 分隔短线 36×3，渐变(#2d73ff → 16% alpha)
             └ 三张卡 grid 3 列，gap 29px，卡高 240px
             右栏（35vw）720×600 的 AI 玻璃主视觉，object-right
footer 69px  #1a1a1a 底，版权所有 + 备案号 + 联系我们（hover 弹二维码）
```

三张卡的内容语法完全一致，这也是它能"一屏讲完"的原因：

| 位置 | 内容 |
|---|---|
| 上部 | 170×132 的功能插画（draft.png / contract.png / case.png） |
| 中部 | 20px 粗标题：文书起草 / 智能合同审查 / 案例智能分析 |
| 下部 | 13px 灰色一行解释（文书：智能生成各类法律文书；合同：风险识别与修改建议；案例：AI 赋能全案深度解构，数据驱动精准胜诉决策） |
| 右下 | 箭头 → ，整卡可点 |

**要点**：卡不是"介绍"，是**入口**。三张卡 = 三个真实功能，点了就进去。

## 3. 美术语言

### 3.1 配色：一个蓝，两个灰，一个白

| Token | 值 | 用途 |
|---|---|---|
| `--primary` | `#0067ae` | 标题强调、AI 徽标描边、箭头 |
| `--foreground` | `#162839` | 正文墨色（标题另用 `#18233f`） |
| `--muted-foreground` | `#47515a` | 次级文字 |
| `--border` | `#d2d8de` | 描边 |
| `--background` | `#fff` | 底 |
| `--radius` | `.625rem`（10px） | 全局圆角基准 |

共 32 个变量（含 `--chart-1..5`、`--sidebar-*` 等 shadcn 标准位）。实测 computed color 里出现 `lab(15.2 ...)` 形式，说明用的是 **Tailwind v4 + oklch** 色彩空间，而不是传统 hex 变量。

**一处真实瑕疵**：变量体系存在，但落地页 markup 里仍有 **21 处裸 hex**（`#e3e9f2`×4、`#18233f`×4、`#8b96ab`×3、`#999`×3、`#1a1a1a`×2、`#1a1a1a`… 共 11 个色值）。换肤时这些不会跟着变。

### 3.2 字号：5 级台阶

`50 → 24 → 20 → 16 → 13`（实测 computed 分布：16×24、13×9、20×4、**14×4**、24×3、50×2）

> 严格的"5 级"是指**有语义角色的 5 档**；14px 那 4 处是零散用法（页脚与卡片注释），不算阶梯里的一级。

- 50px 只给 h1，且 `whitespace-nowrap`
- 20px 给卡片标题与副标题
- 13px 给卡片解释与页脚
- 16px 是默认正文

**代价**：`lg:whitespace-nowrap` 意味着 1366 宽的笔记本上标题不会换行——它选择靠 `lg:min-w-[700px]` 硬撑，而不是允许折行。这是"一屏"路线的必然取舍。

### 3.3 图形语法

- **渐变短线**：`h-[3px] w-[36px] rounded-full` + `linear-gradient(90deg,#2d73ff 0%, rgba(45,115,255,.16) 100%)`。右端渐隐，视觉上像"引出一条线"，比纯色分隔条精致得多，成本 1 行 CSS。
- **卡片阴影**：`0 10px 28px rgba(33,53,96,.06)` —— 极淡，靠 1px 描边 `#e3e9f2` 立住轮廓。
- **AI 徽标**：34×28、`border-2` 主色、白底、字重 extrabold —— 一个"贴纸化"的小构件，让 logo 区有记忆点。
- **主视觉**：720×600 玻璃圆柱 + 悬浮 AI 卡片 + 环绕轨道光点，与产品界面的蓝白玻璃同源。

## 4. 交互与动效

| 交互 | 实测 |
|---|---|
| 卡片 hover | `transition-all duration-300` + 上浮 + 阴影加深 |
| 页脚「联系我们」 | hover 变白 + 弹出二维码浮层（`absolute bottom-[calc(100%+12px)] right-0`，白色圆角卡，`0 8px 30px rgba(0,0,0,.15)`） |
| 落地页入场动画 | **无**（`animation-name` 计数 0） |

CSS 里另有 12 组 keyframes（`sparkle-float` / `sparkle-glow` / `sparkle-orbit-1..3` / `sparkle-scatter` / `wave-scroll` / `risk-flash` / `spin` / `pulse`），但落地页没有启用——它们属于登录后的应用界面。

**判断**：这是"克制动效"的正确姿势——**营销页零动画，交互页才有动效**。我们 2026-10-09 的微动效调研结论与此一致。

## 6. 可借鉴清单（按对我们的价值排序）

### 6.1 首页"一屏讲完"的信息压缩 ★★★

它的思路：把"我们是什么"压缩成 1 句 h1 + 1 句副标 + 3 个入口，其余全部砍掉。

对我们的具体做法（不改我们的多案例结构）：

1. 首页在 1440×900 的首屏内必须完成三件事：**我是谁 / 我做什么 / 从哪进去**。当前我们首屏 490px 的 hero 只完成前两件的一半（"把数据、工程和 AI 工具箱，变成可验证的产品决策"是定位，但没有"最新证据"的入口）。
2. hero 右侧的「本作品集包含」面板（`<dl>`，虚线分隔的 6 行，5 篇案例 / 2 篇数据 / 4 组拆解 / 40 条实测 / 6 份报告）**已经**是"带链接的入口"——每行 `<dt>` 都是指向对应板块的 `<a>`。真正的问题在**数字只有 18px（`text-lg`）**，夹在 14px 的标签旁，体量感被抹平了。对标改法：把 4 个关键数字提到 40–56px 做一条"战果带"，下面保留这 6 行作为明细。
3. 分隔短线：把我们的 hero 与下方 `#featured` 之间的 1px 横线，换成 36×3 的渐隐短竖线（成本 1 行），减少"表格感"。

### 6.2 字号阶梯收口 ★★☆

先说清我们自己的实数（1440 宽首页，computed 统计）：`54×5、51×1、48×1、24×8、18×13、17×15、16×143、14×49、13×16、12×46、11×21`。

但要拆开看，因为其中三段不是"CSS 阶梯"：

| 大字号来源 | 实测 | 说明 |
|---|---|---|
| 首页 h1 | `text-5xl` = **48px** | `src/pages/index.astro:58` |
| 板块 h2 | `text-2xl` = **24px** | 5 个内容板块共用，已经统一（第 6 个 h2 是证据面板的 `text-xs` 小标题） |
| 卡片标题 h3 | **18px** | `Card` 组件 |
| **封面数字** | **54 / 51** | 不是 CSS 字号——是 `Cover.astro` 生成的 **SVG `<text>`**，由 `fitSize()` 按文案长度动态求解（banner 上限 68 / 卡片上限 62，下限 30 / 22） |

**所以真正的问题不是"标题太大"，而是"小字号太散"**：

| 问题 | 实数 | 建议 |
|---|---|---|
| 正文两个值并存 | 17px（prose 默认）×15 与 16px×143 | 统一 **16px**，行高 1.75 |
| 元信息四档 | 11 / 12 / 13 / 14 | 收敛为 **12（标签）/ 14（辅助）** 两档 |
| 标题层级 | 48 / 24 / 18 | **不动**（三级够用） |

收益：11 档 → 7 档。同时**保留 SVG 封面这一处"动态大字"**——那是我们的独有资产（详见 §6.6），不要因为"字号收口"把它误伤。

### 6.3 语义 token：我们其实已经赢了，把它变成门禁 ★★★

- **法典**：32 个变量在册，但落地页 markup 里仍有 **21 处裸 hex（11 个色值）**。换肤时这些不跟着走。
- **我们**（2026-10-27 实测 `src/` 全量 grep）：

| 文件 | hex 出现次数 | 说明 |
|---|---|---|
| `styles/theme.css` | 30 | **定义处**，正确 |
| `styles/report-tokens.css` | 6 | 报告组件的独立色板 |
| `components/*.astro` | **0** | 只有两个 HTML 实体（`&#10005;` `&#169;`），不是颜色 |

结论：**我们的 token 纪律已经比法典严格**。所以这条不是"改造"，而是"固化成门禁"——加一条 `scripts/check-tokens.mjs`：`src/pages/**` 与 `src/components/**` 中出现 `#[0-9a-fA-F]{3,8}` 即构建失败（`styles/*.css` 与 `assets/**/*.svg` 豁免）。骨架直接复用 `check-links.mjs`（遍历 → 正则 → 失败即 `process.exit(1)`）。

### 6.4 图片管线 ★★

我们的证据图是 `dist/assets/dissections/*.png`，实测 134–393 KB/张，原尺寸直出、无 srcset、无 webp。对标做法：

- Astro 内置 `<Image>`（sharp）出 webp/avif + 多档宽度 → 同图约可降到 30–60 KB
- `width/height` 必填（防 CLS），`loading="lazy"` 除首屏
- 首屏图 `fetchpriority="high"`

### 6.5 渐变短线 / 徽标贴纸等微构件 ★★

低成本、高辨识度，可直接搬（不是抄代码，是抄范式）：36×3 渐隐短线、34×28 描边徽标、极淡阴影 + 1px 描边立轮廓。

### 6.6 反过来：我们有一件它没有的东西 ★★★

法典靠 5 张图（含 162 KB 的渲染图）撑首屏；**我们的首页是 0 张图片、30 个内联 SVG**，封面完全由 `Cover.astro` 用参数化 SVG 生成：Georgia 衬线数字 + `fitSize()` 动态求字号 + `headlineMaxEm` 截断。

这意味着：

- 首屏传输 5 个请求就完了（HTML 49.7 KB + CSS 64 KB + 3 个 JS），比法典轻一个数量级；
- 封面可被构建期批量生成、可被 `og` 复用、可换色不改图；
- **这是一条别人抄不走的差异点**：它证明"我能用代码产出视觉"，而不是"我会找素材"。

**结论**：迭代方向不是"补图变成法典那样"，而是"在零图片的类型排版之上，只在**必须有证据**的地方补真实截图"（见计划 P0-3）。

## 7. 明确不借鉴

| 不借鉴 | 原因 |
|---|---|
| 玻璃质感 3D 主视觉 | 需要 3D 渲染产能（渲染 + 修图 + 多尺寸），且与我们"可验证、可核查"的定位相反：主视觉越炫，越像营销页 |
| 单屏 `h-[calc(100vh-60px)]` 结构 | 作品集要展示 5 个栏目 40+ 条目，单屏装不下；强行单屏会把内容藏起来 |
| `lg:whitespace-nowrap` 硬撑不换行 | 在 1366×768 的笔记本上就是横向溢出风险（我们 2026-10-06 踩过一次） |
| 无 og:image | 这是它的缺陷，不是优点 |
