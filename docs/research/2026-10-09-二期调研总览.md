## 1. 四个"前提被推翻"的发现

### 1.1 View Transitions 早就开着

`site/src/layouts/Layout.astro:130` 有 `<ClientRouter />`；构建产物里是 **16 KB** 的运行时（`dist/_astro/ClientRouter...js`，含 `startViewTransition` / `prefetch` / `astro:page-load`）。站点源码里 `theme.ts:48/:52`、`Header.astro:219/:222`、`BackButton.astro:39`、`Main.astro:30`、`ArticleEnhancements.astro:366/:371` 全都已经在用 `astro:page-load` / `astro:before-swap` / `astro:after-swap`。
→ 所以"要不要开 View Transitions"这个问题**不成立**；要做的是"收敛既有行为"。

### 1.2 prefetch 也早就开着，且是"全站链接 + hover"

源码链：`astro.config.ts` 无 `prefetch` 键 → `astro/dist/transitions/vite-plugin-transitions.js:54` 判定 `prefetchDisabled = false` → `astro/components/ClientRouter.astro:151-152` 执行 `init({ prefetchAll: true })`。
官方类型注释原文（`astro/dist/types/public/config.d.ts:1904`）："Enabled by default on pages using the `<ClientRouter />` router."
**线上实测**：hover 一个站内链接后，DOM 里新增 `<link rel="prefetch">` 并产生请求。
→ 站点**不是**"零额外请求"的静态站。不违反"零第三方"红线（全部同源），但叙事要改。

### 1.3 仓库里早有一条 OG 生成流水线，而且拆掉动态 OG 的理由与它无关

`site/scripts/og-template.html`（84 行静态 HTML，1200×630）+ Playwright 截图 → `site/public/og-default.png`（提交 `cca3161`；`docs/STATUS.md:57`；`docs/plans/2026-09-28-…m3…:1049-1050`）。
当初拆掉"动态 OG"（`docs/STATUS.md:51`）的理由是 **satori 依赖 Google Fonts 构建期拉取 + CJK 缺字**，**不是 Playwright**。
→ 那张模板图用的是**旧品牌色 `#006cac` 与旧文案**，与 v0.14 token 不一致；调研已实测「对它截图 = 37,318 B = 现产物字节完全一致」，确认它就是现产物的来源。

### 1.4 reduced-motion 并没有被 Astro 兜住

线上实测：`reducedMotion:'reduce'` 下 Astro **仍然调用** `document.startViewTransition`（no-preference = 1 次 / reduce = 1 次）。且构建产物 `Footer.*.css`（58,356 字节）里 `view-transition` **0 命中**、`astroFade` 0 命中 → **Astro 自带的 reduce 闸门 CSS 根本没进产物**，现在跑的是 UA 默认的根交叉淡入淡出。
权威补充：W3C CSSWG 2024-09-24 决议（issue #10267）方向是"reduce 时 UA 用纯交叉淡入淡出、去掉尺寸/位移动画"，而非完全不动。

## 4. 我推翻或纠正的调研结论（都已写进对应的计划）

1. **「`.prose` 的 65ch 覆盖 `max-w-readable` 的 68ch，所以后者是死代码」——错。**
   实测构建产物 `site/dist/_astro/Footer.BxwaP4fT.css`：`.app-prose{…max-width:65ch}` 在偏移 7111，`.max-w-readable{max-width:68ch}` 在 29183；特异性相同（0,1,0）而后者在后 → **生效的是 68ch**。现状是「三页 68ch / 拆解页 65ch」的口径差，不是死代码。
2. **「详情页插 `Breadcrumb` 降低重复感」——不可行。**
   `Breadcrumb.astro` **无 props**、自带 `app-layout` 外框、`navLabels` 里没有那四个板块 slug、末段还会显示 URL slug（`student-union-platform`）；而详情页上方**已经有 `BackButton`**，加面包屑是双重导航。改用「中文板块 kicker」解决。
3. **「`default-og.jpg` 与实际 `og-default.png` 不一致是个 bug」——不是线上 bug，是陷阱。**
   `config.ts:16` 是 `userConfig.site.ogImage ?? DEFAULT_OG_IMAGE`，而配置里已显式给了 `og-default.png` → 那行是**死回退值**。但删掉配置那行就会构建失败（fail loud，不会静默 404）。顺手修掉。
4. **「maggieappleton 说 prefetch 阻塞跨文档 View Transitions」——对我们的场景不适用。**
   她**根本没用 ClientRouter**（全页搜 `astro-view-transitions-enabled` 零命中），用的是原生 `@view-transition` + 手写 speculation rules；pm-forge 是 **same-document** 过渡，原生的那条路不参与。且该因果在 Chromium/W3C/Astro 一手来源里都核不实。
5. **调研里标为"未核实"的 `scrollama.destroy()`**：已核实存在（`site/node_modules/scrollama/index.d.ts` 的 `ScrollamaInstance` 里有 `destroy: () => void`）。
