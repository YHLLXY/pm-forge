## 0. 一句话结论

**正文宽度一个字都不改**（把 `68ch` 换成等价的 `40em`，纯稳健性修复），把「版头之下、正文之上」那些**已经存在**的内容搬进右侧 384px 的粘性栏，再在栏顶加一个**构建期生成的目录**。466px 空白归零，移动端逐像素不变。

## 1. 最重要的裁决：正文不加宽

这是四路调研里**唯一一个我原计划被推翻**的地方，必须单独说清楚。

原计划是「正文加宽到 704px（44 字/行）+ 右栏」。**W4 的证据否掉了它：**

| 来源 | 约束 | 出处 |
|---|---|---|
| W3C《中文排版需求》clreq §7.1.1.4 | 横排正文**最大 48 字**，参考区间 17–40 字；**行长宜为字号整数倍**（规范性 should） | 【官方规范】https://www.w3.org/TR/clreq/#x7-1-1-4-procedure-for-defining-the-type-area |
| 日文 jlreq（自述基于 JIS X 4051）§2.4.2 | 横组**最大 40 字** | 【官方规范】 |
| 台湾师大 2017 中英混排硕论（引日本視覺設計研究所 1987、林品章/林行健、侯純純/林品章 2011） | 中文*舒适*区 15–30 / 15–25 / 单栏 22–32 字 | 【博客·补充】学术论文，已抓全文 |

**44 字虽然没触碰 clreq 的硬上限，但高于上述每一个"舒适"来源，并且越过了日文的 40 字上限。**

反过来说：**现状 `68ch` `=` 638px `=` 每行 39.9 个汉字，本来就正好卡在 clreq 参考区间顶端与 jlreq 上限上。** 这不是巧合——是我们该守住的位置。

于是最终取 **`40em` `=` 640px `=` 每行整 40 个汉字**：
- 满足 clreq「行长宜为字号整数倍」（40em 就是 40 字）；
- 不越过 jlreq 的 40 字上限（中日双合规，**没有取舍要记账**）；
- 与现状 638px 只差 2px，**阅读体验零变化**，所以这次改动不需要任何"可读性会变差"的辩护。

### 1.1 顺带修掉一个真 bug：`ch` 是错的单位

- CSS 的 `ch` = 西文数字 "`"0` 字形的前进宽度；`0.5em` 只是**测不出该字形时的兜底值**（CSS Values 4）。
- W4 实测：同一份 `68ch` 在 10 种字体栈下摆动 **586.5px → 638.0px（8.8%）**。
- 本项目 `68ch = 638.03px` 的成因已被定位到字体表：`1ch = 0.58642em`，因为 `system-ui` 落到 Microsoft YaHei，其 "`"0` 宽 = `1201/2048em = 0.58643em`（W4 直接解析 `msyh.ttc` 核对）。

**结论：中文正文的长度单位应该是 `em`（或语义更贴切的 `ic`，但 `ic` 的跨浏览器基线未核实，故以 `em` 保底）。**

落地：`src/styles/global.css:49-51` 的 `max-w-readable` 由 `max-w-[68ch]` 改为 `max-w-[40em]`。

**已知微差（必须记账）**：视口宽度在 `(672px, 1024px)` 区间时，正文由 638px 变 640px，**+2px**。低于 672px 时两者都受容器限制、完全相同；≥1024px 后进入两栏栅格。这是本次唯一一处窄屏像素差。

## 2. 右栏放什么：不新增任何内容

调研里最有价值的一条负面结论（00 篇 §7）：**把已经显示过的信息在右栏再放一遍，信息量为零。** 所以右栏不"新增"内容，而是**把现在堆在正文上方的那一堆搬进去**——它们在窄屏本来就出现在正文之前，所以搬进右栏后**移动端的阅读顺序与位置完全不变**。

这不是我发明的结构，是排版传统里的成熟做法（05 篇）：Butterick《Practical Typography》用同一个 `<aside>`，宽屏进边距、窄屏 `float: inherit; position: inherit; width: 100%` 回退成普通块；区别只是我们用 grid 而不是 float。

### 2.1 目录（新增，但零依赖）

- 数据来自 Astro 的 `render(entry).headings`（【官方源码】`astro/dist/content/runtime.d.ts:72-76`），**不需要新依赖、不改 Markdown 管线**。
- 标题 id 已存在且与 `headings[].slug` **同源同一个变量**（【官方源码】`@astrojs/markdown-remark/dist/rehype-collect-headings.js:50-54`），所以锚点必然命中。
- ⚠️ **绝不能在浏览器里读 `textContent` 生成目录**：`ArticleEnhancements.astro:39-58` 已给每个 h2~h6 注入了含 "`#`" 的锚链，读文本会带上 "`#`"。
- 实测条目数 2–10 条（case/analysis 5 条，dissections 4–6 条，toolbox 报告 2–8 条），最长标题 36 字。
- `dissections/[slug]` 正文之后还有 4 个手写 `<h2 class="not-prose">`（任务实测/失败案例库/边界能力清单/四维均分），**不在 `headings` 里**，由页面显式追加进目录。

### 2.2 各页右栏内容（都用现有字段/组件，零编造）

| 页面 | 右栏 | 留在左列（在正文之前） |
|---|---|---|
| case-studies | 目录 · 我的角色 · 技术栈 · 在线访问/源码仓库 · 指标卡 | — |
| analysis | 目录 · 数据集 | 完整报告 iframe（需宽度） |
| dissections | 目录 · 指标卡 · 被测产品/评测口径 · 版本口径 | — |
| toolbox/reports | 目录 | ProvenanceBanner（需宽度） |

**标签不进右栏**：它现在在正文之后，搬进右栏会把它挪到正文之前 → 破坏移动端顺序。**保持原位。**

## 3. 栅格与断点（全部实测，非推算）

```
移动端/平板（<1024px）：完全现状，aside 是普通块，目录 display:none
≥1024px（lg）：grid-cols [minmax(0,1fr) 20rem]  column-gap 3rem
≥1280px（xl）：grid-cols [minmax(0,1fr) 24rem]  column-gap 4rem
always       ：items-start（必须！见 §3.2）
```

| 视口 | 内容盒 | 正文 | 右栏 | 栏距 | **右侧余量** | 正文左缘对齐版头 | 每行汉字 |
|---|---|---|---|---|---|---|---|
| 390 | 358 | 358 | 流内 | — | 0 | ✅ | 22.4 |
| 768 | 736 | 638 | 流内 | — | 0 | ✅ | 39.9 |
| 1024 | 992 | 624 | 320 | 48 | **0** | ✅ | 39 |
| 1280 | 1088 | **640** | 384 | 64 | **0** | ✅ | **40.0** |
| 1440 | 1088 | 640 | 384 | 64 | **0** | ✅ | 40 |
| 1920 | 1088 | 640 | 384 | 64 | **0** | ✅ | 40 |

**右侧余量在所有断点归零**（改前是恒定 466px）；`overflow-x` 全为 0。

### 3.1 两个实现要点（都不是可选的美化）

**① 必须显式指定列，不能靠 DOM 顺序。** 实测：DOM 是 `[aside, article]`，如果不写 `grid-column`，auto-placement 会把 aside 放进第 1 列、article 挤进第 2 列（实测 `articleW` 变成 384、`asideW` 变成 640，完全反了）。正确写法是各自的 `grid-column` / `grid-row` 显式落位。

**② 必须 `align-items: start`。** 【官方规范】CSS Position 3 §3.4：sticky 的位移上限是"其定位盒仍留在包含块内"；而 grid 子项默认 `stretch`（CSS Align 3 §6.2.5）→ **不写就变成栏高 = 行高，sticky 位移恒为 0**。

### 3.2 sticky 实测

在真实页面上注入目标结构并滚动测量：

| 项 | 结果 |
|---|---|
| 正文到 `html` 之间「overflow 非 visible」的祖先 | **0 个** |
| `html` 的 `overflow-y` | `scroll`（根元素，按规范传播到 viewport，**不**破坏 sticky） |
| 滚动中右栏 `rect.top` | **96px（= 6rem，精确贴住）** |
| 正文中段（`scrollY` 1994）时右栏 `rect.top` | **96px**（持续跟随） |
| 滚过容器末尾 | 被正确推走 |

⚠️ **不要给右栏的任何中间祖先加 `overflow-hidden`**（会抢走 scrollport）。注意 `typography.css:34-36` 用的是 `overflow-x-clip`，【官方规范】CSS Overflow 3 §3.1 明确 `clip` **不构成**滚动容器，所以是安全的。

⚠️ 不要改用 `position: fixed`：那会让祖先的 `transform/filter/contain` 抢走包含块（W1 §5）。

## 4. 目录的行为规格

| 项 | 决定 | 依据 |
|---|---|---|
| 元素 | `<nav aria-label="本文目录">` + `<ul>/<li>/<a>` | 【官方规范】APG：多个 landmark 必须有唯一标签，且标签里不要重复 role 名；本站将有 3 个 `<nav>` |
| **不含任何 `h1~h6`** | 栏标题用 `<p>` | `check-headings.mjs:29` 统计所有 h1~h6 并检查跳级；W1 实测 5 家实现里 4 家也不用真标题 |
| 高度上限 | `max-height: calc(100vh - 8rem)` + `overflow-y: auto` | W1：Docusaurus/Nextra 派；W3：实测 10 站里**只有 MDN** 做了上限，其余都会溢出 |
| 当前项 | `aria-current="true"` | 【官方规范】ARIA 1.2：`true` =「集合中的当前项」，页内目录正是"集合中的当前项"；`location` 更偏"环境中的位置"。W1 实测 Starlight 用 `true`。**不要用 `page`**——`Breadcrumb.astro:76` 已占用 |
| 当前项视觉 | accent 色 + 字重 600 + `box-shadow: -2px 0 0` 竖条 | 三条理由：① 不依赖颜色单一通道，满足 WCAG 1.4.1；② `box-shadow` 不占布局宽度、切换零重排（MDN 原文技法，W3 采集）；③ 五家实测**全部没有** `border-left` 竖线，所以竖条只在"当前项"上出现，是状态指示而不是装饰 |
| 点击防闪 | 加一个 `ignoreScrollOnce` 抑制位 | W1：5 家里只有 VitePress（`ignoreScrollOnce`）和 tocbot（`isClick`+420ms）做了；本站 `html` 上有全局 `scroll-behavior: smooth`，不做抑制必然闪烁 |
| 无 JS 时 | 目录照常渲染、照常可点（锚点跳转不需要 JS），只是没有"当前项高亮" | 渐进增强 |

**官方替代方案记录在案**：CSS Overflow 5 的 `:target-current` + `scroll-target-group`（规范自带目录示例），但 MDN BCD 显示 Chrome 135+ / Firefox 不支持 / Safari 不支持 → **本期不采用**，等三家齐了可以删掉这段 JS。

## 5. 动效：只复用站点已有的词汇

用户要求「网页端展示更多的动效」，但红线是"不能太花哨"。做法是**复用站点已有的动效语言**，不发明新的：

| 动效 | 时长/缓动 | 说明 |
|---|---|---|
| 目录当前项切换 | 200ms `ease-out`，只动 `color` / `box-shadow` / `background-color` | 与 v0.16 的 `duration-200 ease-out` 一致 |
| 目录项 hover | 同上 | |
| 右栏卡片 hover | 直接复用 v0.16 已有的 `hover:shadow-lift` | 与列表页卡片同一套语言 |
| 锚点跳转 | 已有全局 `scroll-behavior: smooth`（reduce 下自动关闭） | 不新增 |

**全部在 `prefers-reduced-motion: reduce` 下关闭**；全部只碰 `color`/`box-shadow`/`transform` → **CLS 仍为 0**。

**明确不做**：
- ❌ 右栏阅读进度条 —— `ArticleEnhancements.astro:7-37` 已有顶部进度条 `#myBar`；W3 实测 10 个真实站点**全部没有**进度条。
- ❌ 「回到顶部」新增 —— 已有 `BackToTopButton`；10 站也全部没有。
- ❌ `<h2>` 分节淡入（原 C 轨第 4 项）—— 仍不做。理由不变：这是唯一有 FOUC/首屏闪现风险的一项，且用户诉求是版式而非动效数量。**留作可选后续**。

## 6. 移动端"逐像素不变"的证据

不是承诺，是实测。方法：在真实页面上按目标结构移动 DOM，然后在 390 / 768 两个视口比对每个移动节点的 `top/left/width/height`：

```
{"label":"mobile-390","narrowDiffs":[]}
{"label":"tablet-768","narrowDiffs":[]}
```

**`narrowDiffs` 为空数组 = 所有节点四元组完全一致。** 移动端另有实测：`.__sim_toc 的 display = none`、`aside 的 display = block`、`overflowX = 0`。

实现上保证这一点靠三条：
1. 窄屏不设任何 grid/padding/margin —— aside 与 left wrapper 都是普通块，不贡献盒模型；
2. 目录在窄屏 `display: none`；
3. 右栏里的卡片**保持它们现在的 DOM 顺序**（它们本来就在正文之前）。

## 7. 无障碍与合规（W2 逐条核对）

| 条款 | 结论 |
|---|---|
| **WCAG 2.2 §2.4.11 Focus Not Obscured**（唯一真实风险） | 两栏不重叠、右栏不覆盖正文 → **不触碰** |
| **WCAG 2.2 §1.4.10 Reflow** | `min-width: 1024px` 媒体查询天然满足：400% 缩放下 CSS 视口≈320px → 右栏根本不渲染。**这条让"用断点隐藏"从设计偏好升级为合规做法** |
| WCAG 2.2 §2.4.5 | 不适用（讲"定位页面"，与页内目录无关） |
| WCAG 2.2 §1.3.1 / §2.4.1 | 需 `nav` + 列表 + 唯一标签 → 已满足 |
| WCAG 1.4.1 色彩 | 当前项不只靠颜色（另有字重 + 竖条） |
| `prefers-reduced-motion` | 规范措辞是 "minimize"/"removes or replaces"，不是"移除全部" → 我们关掉自加的动效即可 |
| IO 生命周期 | ClientRouter 下必须在 `astro:before-swap` `disconnect()`（Astro 官方文档；本项目先例 `userbehavior.astro:311-313`） |

**一处有意识的取舍（必须记账）**：W2 建议把目录 `<nav>` 放在 `<article>` **之后**，以便复用现有的 skip link（`Header.astro:34-40`）。但那样窄屏下右栏内容会掉到正文下面，**破坏"移动端不变"这条硬约束**。所以采用 aside 在前的 DOM 顺序，读屏顺序为「事实卡 → 目录 → 正文」——事实卡本来就在最前，新增的只有目录，且目录出现在正文之前对导航是有利的。

## 8. 一条顺手清掉的地雷

`astro.config.ts:42-43` 挂着 `remarkToc` + `[remarkCollapse, { test: "Table of contents" }]`，处于**惰性**状态：

- `remark-toc@9.0.0/lib/index.js:24` 的默认匹配是 `'(table[ -]of[ -])?contents?|toc'` 且**大小写不敏感** → 正文里写 `## Contents` / `## TOC` 就会**自动生成一份正文内目录**，与右栏重复；
- 命中后 `remark-collapse@0.1.2` 会把它包进 `<details><summary>Open Table of contents</summary>` —— **中文站里冒出一句英文**。

实测：**19 个内容文件 / 109 个标题，命中 0**，确实完全惰性。既然本期正式引入目录，建议**直接摘掉这两个插件**（它们没有别的用处），地雷连同依赖一起清掉。

## 9. 新增门禁

`check-links.mjs:7` 的 `SKIP` 正则把 `href="#..."` 整个跳过 → **目录锚点错了现有门禁抓不到**。而改 Markdown 标题是高频操作。

→ 新增 `site/scripts/check-toc.mjs`：对每个含目录的产物页断言「目录里每个 `href="#X"` 都能在同一页找到 `id="X"`」。挂进 `package.json` 的构建链，位置在 `check-headings.mjs` 之后。
