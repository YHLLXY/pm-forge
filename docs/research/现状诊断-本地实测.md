## 一、结论先行

现状的"单调"不是审美口味问题，而是**结构性缺失**：站点把"内容"和"呈现"完全分开了——所有内容都以"标题 + 日期 + 摘要 + 标签"的纯文本形态出现，**全站没有任何一个内容条目有视觉封面**；容器只有 768px，1280px 屏幕上大面积留白；除链接蓝与灰阶外没有第二层色彩，除 1px 边框外没有第二层表面。

一句话：**这是一个排版干净、但视觉信息量接近零的站点。** 它不缺设计品味（首屏大标题、克制的配色、中文引号修正都做得干净），缺的是**视觉锚点、层次与节奏**。

## 三、问题清单（按"为什么看起来单调"归因）

### 🔴 A 级：直接造成"纯文字感"

1. **列表条目零视觉锚点** —— 首页、`/case-studies/`、`/analysis/`、`/dissections/`、`/toolbox/reports/` 全部复用同一 `Card.astro`：蓝色虚线下划线标题 + 日期 + 摘要 + 标签 chip。案例 5 篇、拆解 4 篇、工具报告 6 篇、分析 2 篇，**没有一张图**。证据：`Card.astro:19-45`。
2. **容器过窄、屏幕空置** —— `max-w-app = max-w-3xl` = **768px**；1280px 视口下左右各空约 256px，长页面像"一条竖直文字带"。所有板块都是"标题 → 段落 → 列表 → 边框分隔"的同一节奏。证据：`global.css:26-33`、`index.astro` 七个 `border-b` section。
3. **首屏纯文字** —— hero 只有 h1 + 自我介绍 + 文字链接 + GitHub 图标，没有视觉主体。证据：`index.astro:38-72`、截图 `t1_home-light.png`。

### 🟠 B 级：层次与质感缺失

4. **只有一层表面** —— `bg-muted/40` + `border-border` 1px + `rounded-lg` 反复出现在卡片/指标卡/标签；无 elevation、无 tint 分层、无叠加深度。证据：`Card.astro`、`MetricCards.astro`、`case-studies/[slug]/index.astro:57-66`。
5. **色彩维度单一** —— `theme.css` 仅 6 个色变量、一支蓝 `#006cac`；板块之间无色彩识别度（案例/数据/拆解/故事/工具箱长得一样）。
6. **字体无个性、无数据字体策略** —— `--font-app` 是系统 CJK 栈；无自托管字体、无 display 字体；正文只有 400/600/700；`h3` 强制 `italic`（中文伪斜体观感弱）；全站数字按比例宽度渲染。证据：`theme.css:9-11`、`typography.css:8-10`。
7. **图表与站点视觉语言脱节** —— 图表偏 Plot 默认观感；大数字卡是灰色方块，无单位层级、无趋势暗示、无迷你图。证据：截图 `t2_story-section7.png`、`t4_hover-tip-dark.png`。

### 🟡 C 级：细节与打磨

8. **零动效、零反馈** —— 卡片悬停只有下划线；无视口动效；页面切换可做未做；无 `prefers-reduced-motion` 处理（因为没动效）。
9. **暗色模式是"同一套灰"** —— 深色只有 `#212737` 单层底 + 石板灰边框，缺 tint/glow/层次。证据：`t4_hover-tip-dark.png`。
10. **OG 图一张走天下** —— 分享任意页面都是同一张图，无页面级辨识度。
11. **404 无视觉设计** —— `text-9xl` 的 "404" + `¯\_(ツ)_/¯`，无品牌感、无推荐入口。
12. **首页最强差异化资产没有视觉展示** —— "数据故事"（浏览器内复算）与"工具箱"（三个真实 AI 工具）在首页只有一句话 + 一个按钮。

> 另有 2 处**待核实**（与美化无关，顺手记录）：
> - `src/config.ts:13` 的 `DEFAULT_OG_IMAGE = "default-og.jpg"` 与实际资产名 `og-default.png` 不一致（实际走 `astro-paper.config.ts` 配置，需确认兜底路径可达）。
> - 截图 `t4_hover-tip-dark.png` 中图表 tooltip 仍显示英文通道名 `user count` / `y`，而 STATUS 记录 2026-10-08 已修（9871383）；需确认是修复前截图还是该图未覆盖。

## 四、可复用的既有资产（决定改造成本很低）

1. **设计 token 已集中**：`theme.css` 38 行就是全部色彩定义；`report-tokens.css` 已有"一套视觉语言"的先例，可照抄为全站视觉语言。
2. **图表已走 CSS 变量**：`charts.ts:11 ACCENT = "var(--accent)"` —— **调色板一改，12 张图自动跟随**。
3. **真实图片已存在**：33 张拆解截图 + 3 张工具箱截图在 `public/assets/`，且已有 `manifest.json` 与脱敏脚本，是现成的封面原料。
4. **内容集合结构清晰**：6 个集合 + 字段型 frontmatter（`projectRole/stack/metrics/tags`），加 `cover` 字段属低风险。
5. **构建门禁与视觉无关**：`check-case-studies.mjs` 只校验正文 H2 小节与量化结果，不校验版式 —— 改视觉**不会**触发内容门禁。
6. **View Transitions 已就位**：`ClientRouter` 已在 `Layout.astro` 引入，做页面过渡是"启用"不是"引依赖"。
7. **国内红线已踩过坑**：Google Fonts / 动态 OG / pagefind 都按国内可达性重构过，视觉升级必须沿用同一纪律（自托管、零第三方请求）。

## 五、改造面评估（成本与风险）

| 改造项 | 触及文件 | 碰门禁 | 风险 |
|---|---|---|---|
| 加宽容器 + 列表双列网格 | `global.css`、`index.astro`、各 index 页 | 否 | 需重跑死链/几何走查（导航曾因 7 项挤压折行） |
| 卡片加封面图 | `Card.astro` + 6 集合 schema + 封面生成脚本 | 否 | "封面从哪来"需要方案（见外部调研） |
| 色彩/表面分层 | `theme.css`、`report-tokens.css`、`MetricCards` 等 | 否 | 明暗双主题都要过对比度（a11y ≥90） |
| 自托管字体 | `public/fonts/` + `theme.css` `@font-face` | 否 | **中文自托管字体体积**是最大技术风险；性能红线 |
| 动效 / 视图过渡 | `global.css`、各页 | 否 | 需 `prefers-reduced-motion`；性能预算 |
| 首页英雄区视觉化 | `index.astro` | 否 | 不能牺牲首屏性能（当前 100） |
| 图表配色统一 | `charts.ts`、`report-tokens.css` | 否（story-gates 有 SVG 断言） | 改配色后需复跑 `check:story` 正/反向 |
| 页面级 OG 图 | 构建脚本 + `Layout.astro` | 否 | 动态 OG 曾因 satori/CJK 字体被删，重做要选无字体依赖方案 |

**结论：没有一项需要动内容门禁，全部是呈现层改动。** 风险集中在三处：中文自托管字体体积、Lighthouse 性能保持、明暗双主题对比度。

## 六、附带发现（环境，供后续会话参考）

DSH 的 `write`/`edit` 工具在本工作区（E: 盘 exFAT）**无法写入**——报 `EISDIR: illegal operation on a directory, link ...`，原因是其"临时文件 + 硬链接"的原子写方案在 exFAT 上不可用（exFAT 不支持硬链接）。**在 E 盘写文件必须走 `pwsh` 或 Node `fs`**。这与 pm-forge 被迫从 E 盘迁到 C 盘（NTFS）是同一根因。仓库 `docs/lessons-learned.md` 可追加此条。
