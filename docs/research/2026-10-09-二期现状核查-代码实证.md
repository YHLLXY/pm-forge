## 2. prefetch 现状：**已启用，且 prefetchAll = true，默认策略 hover**

这是本次核查里最反直觉、也最需要写进方案的一条。证据链完整：

1. `site/astro.config.ts` 全文**没有** `prefetch` 键（我已通读，只有 site / integrations / i18n / markdown / vite / env / experimental）。
2. `site/node_modules/astro/dist/transitions/vite-plugin-transitions.js:54-55`：
   ```js
   const prefetchDisabled = settings.config.prefetch === false;
   return code.replace("__PREFETCH_DISABLED__", JSON.stringify(prefetchDisabled));
   ```
   → 没写 `prefetch: false`，所以 `prefetchDisabled = false`。
3. `site/node_modules/astro/components/ClientRouter.astro:150-153`：
   ```js
   // @ts-expect-error injected by vite-plugin-transitions for treeshaking
   if (!__PREFETCH_DISABLED__) {
     init({ prefetchAll: true });
   }
   ```
4. 官方类型注释原文（`site/node_modules/astro/dist/types/public/config.d.ts:1904`）：
   > Enable prefetching for links on your site to provide faster page transitions.
   > **(Enabled by default on pages using the `<ClientRouter />` router. Set `prefetch: false` to opt out of this behaviour.)**
5. 同文件 `:1924` 原文：
   > This value defaults to `true` when using the `<ClientRouter />` router. Otherwise, the default value is `false`.
6. 构建产物实证：`ClientRouter...CYDbzu1r.js` 中出现 4 处 `prefetch`，其中默认值解构为 `W??=e?.prefetchAll??!1`、`G??=e?.defaultStrategy??'hover'`，最后调用处为 `q({prefetchAll:!0})`。

**结论（当前线上真实行为）**：鼠标 hover 任意站内链接会触发预取——优先插入 `<link rel="prefetch">`，浏览器不支持时降级为 `fetch(url, {priority:"low"})`（`@13775` 处的 `J()` 实现）。tap / mousedown / 视口内链接（load 策略）也在监听之列。

**这意味着两条既有事实需要被方案正视**：
- 我们**并不是**「零额外请求」的静态站：hover 就会发预取请求。（不违反「零第三方请求」红线，全是同源，但影响流量与「首次交互后才请求」的叙事。）
- 已知社区报告 prefetch 与跨文档 View Transitions 存在冲突（上一轮调研任务里提到 maggieappleton.com 源码注释）。**待第三份调研文档给结论**；我这边已把 Astro 侧的确切默认值钉死，可直接用于复现。

## 4. 阅读宽度（顺手核清一个我以为的 bug）

- `site/src/styles/global.css:39-41`：`@utility max-w-readable { @apply max-w-[68ch]; }`
- `site/src/styles/global.css:31-33`：`@utility max-w-app { @apply max-w-[1120px]; }`
- `site/node_modules/@tailwindcss/typography/src/styles.js:1414`：`.prose` 自带 `maxWidth: '65ch'`

所以：
- 只写 `app-prose` 时宽度是 **65ch**（Tailwind Typography 的默认值），不是「撑满 1120px」。
- `site/src/pages/dissections/[slug]/index.astro:78` 只写 `app-prose mt-8 w-full`（实为 65ch），而 case-studies:102 / analysis:83 / toolbox reports:66 写 `app-prose max-w-readable`（68ch）→ **3ch 的口径不一致**，不是破版 bug。

结论：二期若要统一阅读宽度，这是一处**一行改动**；但优先级低，且应明确「统一到 65 还是 68」，不要默默改。
