# 右栏设计传统：边注（sidenotes）与旁注（margin notes）

> **这一篇解决的不是「目录怎么做」，而是「右边那一列在排版传统里本来该放什么」。** 结论直接影响 06 篇的方案取舍。

## 摘要（可直接执行的结论）

1. 我们遇到的「正文窄、右边空一片」在排版学里有名字，gwern 的原话是 **"a narrow river of text flowing down a vast blank map"**（一条窄河在巨大的空白地图上流）。这是**已知问题，有成熟解法**，不是我们的设计失误。
2. 成熟解法就是**把那一列用起来放"内容"**，而不是留白——这一类内容叫 **sidenote（边注，有编号、锚定正文某处）** 或 **margin note（旁注，无编号，贴着某段正文放）**。
3. 业界实现分成两派：**Tufte-CSS 派（编译期静态 HTML + CSS，float 出边）** 与 **运行期 JS 派（sidenotes.js 等）**。gwern 明确推荐前者：**"fast & simple (using only compile-time generation of sidenotes, rendered by static HTML/CSS)"**。
4. **Butterick 派用 `<aside>` 元素 + CSS 定位**，窄屏回退成 **100% 宽的行内块**。这条回退规则正是我们「移动端保持现状」的现成答案。
5. 已知代价必须记住：**Tufte-CSS 明确"不做避让"**（原文：*no measures are taken to avoid collisions or overlaps*）。我们若照搬 float，会和粘性目录打架 → 我们要用 grid，不用 float。
6. 无障碍上不能照抄 Tufte-CSS 的 checkbox 折叠：Koos Looijesteijn 列出了一份**语义化边注的要求清单**，是本篇最有价值的一份验收口径。

## 1. 定义与问题命名

【一手·原文】gwern，《Sidenotes In Web Design》（created 2020-08-06，modified 2025-04-06，status: finished，confidence: certain），https://gwern.net/sidenote

> **Sidenotes** & **margin notes** are a typographic convention which improves on footnotes & endnotes by instead putting the notes in the page margin to let the reader instantly read them without needing to refer back and forth to the end of the document (endnotes) or successive pages (footnotes spilling over).

他对两者的区分（原文）：

> If it is numbered & anchored to a specific point in the text, I call it a 'sidenote'; if it is unnumbered & is merely placed next to a body of text, then I call it a 'margin note'.

**问题命名（原文，直接对应我们的处境）**：

> **Making use of margins.** Because it's uncomfortable to read sentences which wrap from edge to edge, particularly for large widths, documents use short lines. But with large screens, many documents have equally large margins, and **wind up looking like a narrow river of text flowing down a vast blank map.**

→ 所以「正文要短」和「屏幕很宽」本来就会冲突，**正确做法不是把正文拉长，而是把边距用起来**。这与 00 篇 §1.1 的量化结论（638px / 每行 39.9 汉字 / 466px 空白）完全吻合。

## 2. Tufte-CSS：最流行的实现

【一手·源码】edwardtufte/tufte-css，`tufte.css`（经 jsDelivr 镜像取得，9494 字节）：
https://cdn.jsdelivr.net/gh/edwardtufte/tufte-css@gh-pages/tufte.css

**桌面（默认）规则原文：**

```css
.sidenote,
.marginnote {
    float: right;
    clear: right;
    margin-right: -60%;
    width: 50%;
    margin-top: 0.3rem;
    margin-bottom: 0;
    font-size: 1.1rem;
    line-height: 1.3;
    vertical-align: baseline;
    position: relative;
}
```

即：**旁注从正文里 float 出去、负外边距 -60% 推到边距、宽度取正文的一半**。

**窄屏规则原文（`@media (max-width: 760px)`）：**

```css
label.margin-toggle:not(.sidenote-number) { display: inline; }
.sidenote, .marginnote { display: none; }
.margin-toggle:checked + .sidenote,
.margin-toggle:checked + .marginnote {
    display: block; float: left; left: 1rem; clear: both;
    width: 95%; margin: 1rem 2.5%;
    vertical-align: baseline; position: relative;
}
label { cursor: pointer; }
```

**配套标记（gwern 原文引用）：**

```html
<label for="sn-extensive-use-of-sidenotes" class="margin-toggle sidenote-number"></label>
<input type="checkbox" id="sn-extensive-use-of-sidenotes" class="margin-toggle">
<span class="sidenote">This is a sidenote.</span>
```

→ **纯 CSS 折叠，零 JS**：一个隐藏 checkbox + `:checked + .sidenote` 选择器。

【一手·原文】gwern 对该实现的两点评价（重要，是它的**代价**）：

> By default (on desktop), the notes are floated right into the margin; **no measures are taken to avoid collisions or overlaps** (presumably if you have that problem, you ought to just rewrite your page or fix it yourself).

> On narrow windows & mobile, a media-query overrides the regular CSS, so the margin notes are **not floated, simply indented, and toggled**.

### 2.1 为什么我们不能照搬 float

- 我们要在同一列放**粘性目录**。`float` 与 `position: sticky` 是两套定位机制，混用会互相打架（float 元素不参与 sticky 的包含块计算，且 `clear: right` 会强制换行）。
- Tufte 自己承认**不做避让**。我们没有专职编辑去手工调版式，必须用**结构性**手段（grid 单列）保证不重叠。
- 我们的正文在 `app-prose` 里，float 出边会破坏 `prose` 的既有节奏。

→ **结论：借它的"用边距"思想与断点回退策略，不借它的 float 实现。**

## 3. Butterick：用 `<aside>` 而不是 float

【一手·原文】gwern 转引 Matthew Butterick《Practical Typography》(2013) 的实际 CSS：

```css
title-block, aside {
    display: block;
    float: left;
    position: absolute;
    margin-left: 0;
    left: 2.5rem;
    width: calc(2.5rem * 3);
    text-align: right;
    list-style-type: none;
    clear: both; margin-bottom: 1rem;
    font-variant-numeric: normal;
}

@media all and (min-width:1200px) {
    aside { left: 0; width: calc(2.5rem * 4); }
}

@media all and (max-width:520px) {
    title-block, aside {
        float: inherit;
        position: inherit;
        width: 100%;
        text-align: left;
    }
    ...
}
```

**这条对我们的价值最大**：窄屏时 `float: inherit; position: inherit; width: 100%` ——
**同一个 `<aside>` 元素，宽屏进边距、窄屏回到正常文档流、占满 100% 宽。**

gwern 的描述：

> The approach is HTML/CSS, but using `<aside>` elements, which are styled in CSS... They fallback to pop-ins **defaulted to expanded** on narrow/mobile windows.

→ 注意 Butterick 的窄屏回退**默认展开**（不像 Tufte 需要点一下）。这正是我们要的：**移动端用户不该为了看到内容而多点一次。**

## 4. Koos Looijesteijn：语义化边注的验收清单

【一手·原文】Koos Looijesteijn，《Semantic sidenotes for the web》(2019)，
https://www.kooslooijesteijn.net/blog/semantic-sidenotes
（经 gwern 转引，原文为其自述需求清单）

> - The span that the sidenote refers to should have a **proper semantic HTML element** (no abuse of elements made for other purposes)
> - The content of the sidenote should have a similarly valid HTML tag. Additionally:
>   - The sidenote content may contain span elements such as `<a>` and `<em>`.
>   - The sidenote content **may contain clickable elements that can receive keyboard focus**.
>   - The sidenote content must be stylable.
> - The elements should **not cause auto closing of their parent `<p>` tag**.
> - **Reader modes and apps like Pocket and RSS readers should show sidenote content in a typographically acceptable way.** That means at the very least that I can't rely on website's CSS to place and style the elements correctly.
> - The sidenote content should be **read by screen readers, in a flow that makes sense**. That likely means the two parts should be placed together.

**这份清单可以直接当我们右栏的验收口径**（逐条映射见 §5）。

gwern 另记了反面教材（同样有价值，是"别做什么"）：

> ILoveTypography.com ... uses figure captions --- just `<figcaption>` with a special class **inside an empty `<figure>` with no images**! This is **invalid HTML**, fails badly in some cases (eg. ... one margin note is almost unreadable because **it overlaps with a giant pull-quote illustration**), and **has no advantage over a `<span>`** that I can find.

→ 教训：**不要为了一个视觉效果去滥用语义元素**；重叠不是"美观问题"，是**可用性缺陷**。

## 5. 对本项目的适用性

| 传统做法 | 我们怎么做 | 理由 |
|---|---|---|
| Tufte 的 `float: right + margin-right: -60%` | ❌ 不用 | 与粘性目录的定位机制冲突；Tufte 自己承认不做避让 |
| 用 `<aside>` 承载边距内容（Butterick） | ✅ **采用** | 语义正确、可被样式控制、无标题元素（不污染 `check-headings`） |
| 窄屏回退成 100% 宽的普通块（Butterick `max-width:520px`） | ✅ **采用，且更强** | 我们的 DOM 顺序里 aside 本来就在 article **之前** → 窄屏回到「上文下表」时**位置与现状完全一致**，真正做到移动端零变化 |
| 窄屏折叠成"点一下才展开"（Tufte checkbox） | ❌ 不用 | Butterick 的"默认展开"更好；而且我们窄屏内容本来就在页面上方，**根本不需要折叠控件** |
| 编译期生成、静态 HTML/CSS、零 JS（gwern 推荐） | ✅ **采用** | 与"零第三方运行时请求"红线一致；Astro 的 `headings` 是编译期数据 |
| 边注编号 / counter | ❌ 不用 | 我们没有脚注语义，编号会是假的信息层级 |
| 边距里放「与正文某处强绑定」的注释 | ⚠️ 部分采用 | 我们没有脚注内容；但**与正文相关的元信息/口径说明**属于同一类（见 06 篇） |
| RSS / reader mode 下仍可读（Looijesteijn） | ✅ **必须满足** | 我们的内容在 HTML 里就是普通元素，不依赖 CSS 才可见 |

### 5.1 Looijesteijn 清单 → 我们的验收口径

| 他的要求 | 我们的对应 |
|---|---|
| 用正确的语义元素 | `<aside>` + `<nav aria-labelledby>`，**不含任何 h1~h6** |
| 内容可样式化、可含可聚焦元素 | 目录是 `<a href="#slug">`，天然可聚焦 |
| 不破坏父 `<p>` | 右栏是 `<main>` 的直接子元素，不在 `<p>` 内 |
| reader mode / RSS 下可读 | 全静态 HTML，无 CSS 依赖；窄屏不隐藏内容（内容仍在文档流上方） |
| 屏幕阅读器阅读顺序合理 | ⚠️ **需实测**：`<aside>` 在 DOM 中位于 `<article>` **之前**，读屏顺序会是「元信息 → 目录 → 正文」。这与视觉顺序（正文在左、栏在右）不一致。**06 篇必须给出结论** |
